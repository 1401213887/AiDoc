2寄存器(GPR)→ occupancy 换算机制

这套机制在 740 和 750 上完全相同，是理解高 GPR 影响的核心：

寄存器文件容量(固定)÷ 单 wave GPR 占用= 可同时活跃的 wave 数→ occupancy→ 延迟隐藏 / 吞吐
概念说明
fiber最小执行单位，对应一个工作项 / 一个像素或顶点
wave一组锁步执行的 fiber，Adreno 波大小常见 8/16/32/64/128，由 GPU 系列与编译器决定
全精度寄存器128bit，可存 4 个 FP32 或 8 个 FP16
半精度寄存器64bit，可存 4 个 FP16，占用按"半个"计
活跃 wave 数一个 SP 内最多可并行的 wave 数；受寄存器占用 + 寄存器文件大小限制，Adreno 通常上限 16 波
核心因果链：GPR 数值高 → 单 wave 占用大 → 活跃 wave 变少 → occupancy 掉 → 访存延迟无法被其他 wave 填补 → ALU 空转 (stall)。占用极端超标时还会触发 register spill(寄存器溢出到显存)，代价更大。

3GPR 数值高时，8Gen2 与 8Gen3 的差异

① 寄存器行为本身：高度一致

同代架构、同样的 128bit 全精度寄存器粒度。同一个 shader、同样的 GPR 数值，在两者上换算出的活跃 wave 数大概率相同。GPR 拉高导致 occupancy 下跌的"拐点"位置基本一致——这一层看不出明显区别。

② 真正拉开差距的是"掉了 occupancy 之后谁更扛"

低 occupancy 场景8Gen2 (Adreno 740)8Gen3 (Adreno 750)
单 wave 推进速度受限于较低频率频率高 ~30%，stall 绝对时间更短
访存往返代价L3 较小，更易 cache missL3 更大 + 带宽 +14%，访存更省
综合表现occupancy 不足的惩罚更明显同样掉 occupancy，但"惩罚更轻"

现象总结：同一个高 GPR shader，两者都会掉 occupancy，但 8Gen3 的性能损失更小——靠的是频率和缓存，不是寄存器更多。

③ register spill 临界点

GPR 高到溢出显存时，8Gen3 更大的缓存和更高带宽能稍缓解 spill 的访存代价。但溢出本身要尽力避免，靠硬件兜底是下策。

5实操优化建议

降低 GPR 占用的手段

  • 多用 mediump / FP16 half 精度变量
  • 缩小向量、避免超大动态向量
  • 把变量定义挪近使用点，缩短活跃区间
  • 用数组替代大量独立变量；尽量用静态常量赋值
  • 合并可分组的纹理获取(每组 <15)

调优策略

  • 不要为单颗芯片单独调寄存器——两者行为一致，一次优化两边受益
  • 优先用 8Gen2 调：频率低、缓存小，occupancy 不足惩罚更明显；在它上面达标，到 8Gen3 余量更足
  • 盯 ALU 波阵列占用 % 而非 GPR 绝对值
  • 真机测试 ≥10 分钟，观察热降频下的表现
一句话结论：8Gen2 与 8Gen3 的寄存器配置/行为基本一致，GPR 高对两者的"机制影响相同"；区别在于 8Gen3 靠更高频率 + 更大缓存，让低 occupancy 的性能惩罚更轻。优化应针对寄存器占用本身下手，并以 8Gen2 为基准调，而非依赖任一芯片的硬件余量。
