一、UE 特效方案基础入门

横向对比之前，先把 UE 特效体系的地基拉通：粒子系统怎么演进、一个特效实例怎么跑起来、资产怎么构成、在游戏里分几类。懂这套，后面各章的对比才有落点。

1.1 两代粒子系统：Cascade → Niagara

Cascade（UE4 早期，存量项目在用）

  • 模块化堆叠：Spawn / Lifetime / Initial Velocity / Color over Life 等模块像搭积木一样拼出一个发射器，手艺人友好
  • 但数据流是"固定的模块序列"，跨模块共享数据、读引擎场景信息（RT / 距离场 / 网格）能力弱
  • 移动端现状：幻塔 / 龙族幻想 / 永劫无间手游等 UE4 手游大量存量特效仍跑在 Cascade 上；优化手法（关碰撞、Atlas 压缩）与 Niagara 通用

Niagara（UE4.4 引入，UE5 主推）

  • 数据驱动 + 可编程：System → Emitter → Particle 三层，用 Data Interface 接引擎数据（场景 / 网格 / 音频 / RT / 距离场），用 Simulation Stage 做可编程模拟
  • 能力上限远高于 Cascade（GPU 模拟、粒子间通信、RT 读写），但移动端能力集受限，多数项目只取 CPU 模拟 + Sprite 渲染这一小撮
  • 深度定制案例：无限暖暖从代码底层重构粒子碰撞、用粒子间通信做"落叶受脚步气流影响"的交互

1.2 头部 UE 手游的粒子系统选型现实

回到 11 款案例本身：它们到底跑 Cascade 还是 Niagara？答案几乎从不由"技术先进性"决定，而是由引擎版本 + 立项时间决定。厂商极少公开声明选型，下表按证据等级标注。

游戏引擎 / 立项-上线粒子系统选型证据等级
PUBG MobileUE4（2017 立项 · 2018 上线）Cascade🔴 硬约束：2018 年 Niagara 未稳定，只有 Cascade
和平精英UE4 改（2018-2019 上线）Cascade🔴 硬约束：UE4 早期项目
龙族幻想UE4（2016 立项 · 2019 上线）Cascade🔴 硬约束：UE4.2x 时代；刘冰提的"GPU 粒子"即 Cascade 的 GPU 发射器
黎明觉醒UE4（2019 立项 · 2023 上线）Cascade 为主🟡 推断：UE4 生产项目，迁移成本高
暗区突围UE4.26（2020 立项 · 2023 上线）Cascade 为主🟡 推断：天气 / 体积云是自研材质，粒子走旧管线
幻塔UE4.26（2019 立项 · 2022 上线）Cascade 为主🟡 推断：2022 年前生产项目用 Niagara 风险高
三角洲行动UE4 改（2020 立项 · 2024 上线）Cascade + 大量材质驱动特效🟡 推断：GDC2025 讲的特效几乎全是材质 / 数据驱动，粒子反而次要
永劫无间手游UE4（端游 2019 开发 · 手游 2024）Cascade（沿袭端游管线）🟡 推断：沿袭端游资产最合理
鸣潮UE4.26（2020 立项 · 2024 上线）Cascade 为主，可能试点 Niagara🟡 推断：库洛深度定制引擎，但 UFSH2023 只讲渲染不讲粒子
王者荣耀世界UE5（2021 立项 · 2025 上线）Niagara🟢 高置信：UE5 新项目用 Cascade 无意义（官方已弃用）
无限暖暖UE5（2023-2024 上线）Niagara✅ 直接证据：UFSH2024 明确讲 Niagara 逐粒子编程 / 粒子间通信
选型的决定性变量是版本时间线，不是技术优劣
  • Niagara 首次实验性接入 UE4.4（2015），成熟可生产要等到 UE4.23–4.26（2019–2020），UE5（2022）全面主推并弃用 Cascade
  • 2019 前立项的 UE4 手游 → Cascade 无疑（PUBG Mobile / 和平精英 / 龙族幻想）
  • 2020–2022 的 UE4.26 项目 → Cascade 为主（迁移成本 + 团队习惯）
  • UE5 项目 → Niagara（无限暖暖有官方演讲直接证实）
自研封装才是真相
头部团队的真实架构是三层：自研特效框架（配置表 / 技能打包 / 热更 / 分级——美术真正面对的东西）→ 驱动 粒子系统（Cascade 或 Niagara 只作底层执行器）→ 决定观感的是 材质 + 序列帧 Atlas + 预算治理。所以"用 Cascade 还是 Niagara"对很多团队是伪命题，这也是公开资料查不到直接答案的原因。

1.3 一个特效实例怎么跑起来

概念作用
Niagara System一个完整特效（如"一次爆炸"），由 1~N 个 Emitter 组成，对应一个 .uasset
Niagara Emitter一种粒子行为模板（"爆炸的火焰" / "爆炸的碎片"），决定 Spawn 速率、生命周期、运动、渲染方式
ParticleEmitter 生成的单个实例（一颗火星、一片烟）
Spawn 时机Burst（一次性爆发，如爆炸）vs Rate（持续发射，如火把 / 瀑布 / 雨）
Data InterfaceNiagara 与外部世界的通道：采样网格 / 距离场、读写 RenderTarget、接音频与场景灯光
Simulation Stage可编程 GPU 模拟阶段（移动端受限，需评估能力集再启用）
渲染器Sprite（面片，最省）/ Mesh（网格）/ Ribbon（条带拖尾）/ Ribbon Trails / MCParticles
粒子材质粒子本质是"带材质的面片"，材质决定观感：Additive（加色，火焰）/ Translucent（透明，烟雾）/ Masked（遮罩，弹片）
为什么 Simulation Stage 在移动端受限

Simulation Stage 的本质是"把粒子模拟做成 GPU 上的可编程 Compute 多阶段流水线"（粒子数据当 buffer，用 Compute 级联读改写再渲染）。它需要的四样东西在移动端各自缩水，叠加成"受限"：

  1. 能力集 / API：GLES 中低端无可靠 compute（暗区突围 GDC2022 原话"许多移动设备不支持计算着色器"→ LUT 改用像素着色器分帧更新）；iOS Metal 计算支持最好——Android 下限 vs iOS 上限分裂巨大。UE 的 Feature Level（ES3_1 / SM5）直接决定 GPU emitter 能否编译
  2. TBDR 架构：粒子 buffer 是跨 tile 的全局随机访问数据，用不上 on-chip tile 内存，每次读改写打到 L2 / DRAM；多 stage 级联 = 同一份粒子数据在 DRAM 上来回跑 N 趟，带宽 + 发热双重打击
  3. sim→render 强制同步：compute 写完渲染读，每个特效一个隐式 barrier，频繁 compute↔graphics 切换产生流水线气泡（CPU 模拟无此跨管线同步）
  4. 驱动稳定性：移动驱动对 SSBO 随机写 / 原子 / 动态 buffer 扩容（粒子增长触发 realloc）历史 bug 多——UE 默认关 GPU 排序（fx.Niagara.AllowGPUSorting=0），默认 GPU 碰撞不可用（无限暖暖重构粒子碰撞、火焰案例改用 Cylinder Location 模拟聚集）
  5. 性能预算：移动 GPU 核少频低，Simulation Stage 跟 BasePass / 后处理抢同一块 GPU，复杂 multi-stage 模拟在手机上吃不消

"评估能力集再启用"的实操 = 分级开关：GLES 中低端默认 CPU 模拟，Vulkan 旗舰 / iOS Metal 才评估 GPU 模拟；GPU 排序 / 碰撞 / 复杂流场默认关；GPU 路径必须保留 CPU fallback 随时切换。

1.4 资产构成与制作流程

  • 资产链：序列帧贴图 / Atlas → 粒子材质（Unlit / Additive / Masked + 时间动画）→ Niagara System / Cascade → 触发（技能 / 命中 / 环境 / 蓝图）
  • 制作流程：设计概念 → 出序列帧素材（手绘 / 引擎预渲染 / Houdini 等工具离线生成）→ 拼 Atlas → 写粒子材质 → 调粒子参数 → 挂触发 → 分档调优
  • 移动端差异：素材按机型分级（贴图 512 上限）、压缩格式（ASTC / ETC2）、材质强制走 Mobile Shader Model——预算在"产出资产"这一步就定死，而不是等上了真机再救

二、核心结论速览

特效的四层心智模型

  • 材质驱动层：UV 走形 / WPO / 溶解 / 扫光 / 闪烁——不产生粒子，零排序成本
  • 粒子系统层：Niagara / Cascade / 自研——移动端以 CPU 模拟为主，GPU 粒子受限于能力集
  • 屏幕空间层：体积光 / 光晕 / 冲击波——一次全屏 Pass 换全局表现
  • 生态演出层：天气 / 生态战损 / 大招演出——数据驱动，跨模块共享状态

移动端特效三条铁律

  • 预算先行：单技能粒子约 200–500，DC 10–20，贴图 256–512（端游量级减一个数量级）
  • 半透明克制：Overdraw 是 TBDR 头号杀手，特效叠加尽量 ≤2 层、能用 Mask 不用 Alpha
  • 模拟降级：碰撞 / 物理 / GPU 模拟逐档降级；能烘焙的烘焙（Flipbook、Atlas 通道压缩）

头部 UE 手游共性手段

  • 材质分级（PC 丰富 / 移动端简化），同一资产多级 LOD
  • 动态天气 / 体积云做成 LUT 分帧更新，避免每帧全量计算
  • 数据驱动生态特效（Clipmap 健康度 → 燃烧 / 战损，零材质变体）
  • 自定义 RHI 修改（Mali FPK、Adreno 写带宽坑）保特效下限
总体取舍
UE 手游特效的本质不是"把端游特效做小"，而是换一套技术底座：TBDR 架构下带宽与 Overdraw 取代"粒子数量"成为第一瓶颈，头部团队普遍把特效做进材质分级（同一个资产在不同机型走不同 Shader 路径）、把全局氛围做成数据驱动（Clipmap / LUT / 天气状态），让"便宜的特效"与"贵的特效"由同一套数据在不同设备上分别表达。产品定位决定特效策略：FPS 重写实演出（暗区、三角洲），二次元重风格化半透明与演出（鸣潮、永劫）。

三、概念辨析

特效专题最容易混淆的概念，先拉通口径（下表站在移动端视角，标注每项的代价排序）。

概念是什么移动端代价 / 非线性点
Niagara vs Cascade UE 两代粒子系统。Niagara 数据驱动、可编程（Data Interface / CPU-GPU 混合模拟）；Cascade 为 UE4 早期模块化系统，UE5 已边缘化 Niagara GPU 模拟（Compute / Simulation Stage）在移动端能力集受限；很多 UE 手游团队选型时直接砍掉 GPU Emitter，或深度定制 Niagara 源码（如无限暖暖重构粒子碰撞）
GPU 粒子 vs CPU 粒子 GPU 粒子在 Compute / VS 阶段模拟，省 CPU；CPU 粒子逐颗跑 Game Thread 逻辑，可碰撞可交互 移动端 GPU 粒子受无 Geometry Shader / 无 Tessellation / Compute 上限限制；祖龙（龙族幻想）称 GPU 粒子吞吐量可达 CPU 粒子百倍级，但落地仍需顶点色 / VT 配合。CPU 粒子 + 定点数预算仍是多数 UE 手游的默认底座
Flipbook / SubUV / Atlas 序列帧动画三种承载：Flipbook=整帧序列；SubUV=UE 内置的 UV 网格动画；Atlas=多序列打包到一张图（可跨通道压缩） 大序列帧贴图是带宽大户。行业做法：4 张火焰序列帧压缩进一张 512×512 RGBA——R 通道存火焰、G 存烟雾、B 存火花、A 存透明度，一份采样成本换四路表现
材质驱动特效 vs 粒子驱动 材质驱动：UV 走形、World Position Offset、溶解、扫光、Fresnel 边缘光——本质是 Shader 动画，无实例；粒子驱动：发射 / 回收 / 生命周期 材质驱动零排序零实例成本，是移动端"廉价特效"第一选择（永劫的丝滑拖尾闪电即 UV 速度 + 法线绕动实现）；但材质指令数过线（如 180 条 → 65 条）是常见翻车点
屏幕空间特效 体积光（丁达尔）、Bloom 光晕、镜头光晕、冲击波 / 折射扭曲、Hit Stop 全屏闪——一次 PostProcess 覆盖全屏 和平精英"极清"丁达尔、镜头光晕即此层。代价是像素着色成本与全屏 Pass 依赖；移动端 SceneTexture:SceneColor 采样是"性能杀手"级操作，常见替代是噪声纹理 UV 扰动伪造扭曲
半透明排序 vs OIT 半透明按深度从前到后排序再混合；OIT（顺序无关透明）无需排序，逐像素维护透明列表 OIT 移动端基本不可行（需 SM5.1 / Rasterizer Order Views）。排序错误的兜底：统一 Sort Priority、关闭 Depth Test、半透明自遮挡走 Custom Depth

四、UE 特效体系：引擎机制对比

UE 本身在移动端暴露的特效杠杆与对应 CVar / 模块，是每个 UE 手游项目特效调优的公共底盘。

机制适用对象原理移动端代价 / 限制
Niagara CPU 模拟 通用技能 / 环境特效 Game Thread 逐颗更新，Data Interface 读引擎数据 可碰撞可交互（无限暖暖落叶受气流影响即此）；数量上限由 CPU 预算决定
Niagara GPU 模拟 大数量烟尘 / 流场 / 涟漪 Compute / Simulation Stage 批处理 移动端能力集受限：GPU 排序、复杂 Vector Field、粒子碰撞常被禁用。官方清单：fx.Niagara.AllowGPUSorting=0 关 GPU 排序
Niagara Render Target / 距离场读写 高单位数 RTS / 大面积流体 粒子写 RT 再由材质采样，或采样 Distance Field 做环境交互 Epic 在 Unreal Fest Orlando 2025「Chasing Waterfalls」演示：移动 RTS 用 Niagara 读写 RT + 多值打包（一个 float 存多值）+ 距离场做特效，属进阶玩法，成本需精细核算
Cascade 遗留系统 UE4 存量项目 模块化粒子发射器 多数 UE4 手游仍跑 Cascade（幻塔 / 龙族幻想 / 永劫等），Niagara 迁移成本高；优化手法（碰撞关、Atlas 压缩）两代通用
材质粒子（无实例特效） 武器拖尾 / 边缘光 / 地面法阵 纯 Shader 动画：UV 走形、Panner、溶解、Fresnel 零实例成本，移动端首选；但材质指令数要压（案例：火焰特效 180 → 65 条，GPU 15ms → 4ms）
Mobile Shader Model 全部移动端材质 裁剪不支持的特性，输出低开销 Shader 特效材质强制 Mobile SM；禁用复杂 Material Function、Texture ≤1024、避免动态材质参数
LOD 分级 粒子系统 / 特效蓝图 按距离 / 画质档切 Spawn 数量、贴图 Mip、是否启用子发射器 远距离直接关特效 / 降 Spawn Rate；Burst 拆分 2–3 次错帧避免"同步死亡"抖动
EarlyZ / PrePass 不透明 + Mask 特效 r.Mobile.EarlyZPass 先写深度，让含 clip 的 Mask 也能 early-z kill Draw Call / binning 翻倍；从抓帧看多数头部项目没开 PrePass（低端机压力），Mask 特效通常受限于此

五、端游方案为何在移动端失效

这是模式 B 的核心价值点——头部 UE 手游的特效团队几乎全部踩过"端游逻辑直接上手机"的坑，失效根因集中在 TBDR 架构与移动能力集。

架构级失效（TBDR / Tile-based）

  • Overdraw 乘数成本：移动 GPU 逐 Tile 渲染，半透明多层叠加的像素着色次数乘数增长——两个粒子重叠即可让 Shader Complexity 视图变白。UWA 经验：移动平台填充倍数均值控制在 3.0 以下
  • 无 Geometry Shader / 无 Tessellation：端游粒子常见的 GS 分发、曲面细分做不了，Ribbon / 复杂 Mesh 粒子退化为 Sprite
  • OIT 不可行：顺序无关透明需要 SM5.1 + ROV，移动端无解，只能排序 + 混合模式治理
  • 带宽与发热：大贴图、多 Pass、全屏后处理每像素读写都会触发降频——4K 序列帧贴图在手机上就是发热源

能力集失效（Feature Set）

  • GPU 粒子碰撞 / 复杂 Vector Field 被禁：Niagara GPU 排序都要关（AllowGPUSorting=0），端游流场特效直接不能跑
  • SceneTexture:SceneColor 采样：常用于热扭曲 / 折射 / 反射，在移动端是"性能杀手"，案例中一处采样即让 60fps 掉到 30fps，需用噪声 UV 扰动伪造
  • 深度回读坑：Mali 上 Depth Fetch 会打掉 FPK（Early-Z），指令数异常升高（鸣潮 UFSH2023 踩坑），需改走 GBuffer 重新编码
  • 硬件能力差异：从骁龙 625（PUBG Mobile 低档 60fps 基准）到 8Gen3，十年机型跨度决定必须做"端手独立配方"而不是同一特效按比例缩放
本质
端游特效的默认假设是"GPU 时间足够 + 显存足够 + 有能力集"，移动端三者全部被破坏。因此头部团队把特效设计逻辑整体反转：先在材质 / 数据 / LOD 层把"不花钱的表现"做足，再花预算买粒子——而不是反过来。

六、资源治理层：让特效"跑得动"

粒子预算表（手游 vs 端游，行业通行参考）

维度端游典型手游典型（骁龙 870 档）备注
单技能粒子数5000–10000200–500（含拖尾 / 光晕辅助粒子）王者荣耀单技能即此量级
Draw Call50–10010–20合并相同材质粒子批次可大幅收敛（王者 GDC2024：团战 15–60fps → 45–60fps）
贴图分辨率2048–4096256–512Android ASTC / ETC2，iOS 硬件压缩
渲染模式GPU + CPU 混合以 CPU 模拟为主GPU 粒子限能力集场景

贴图治理

  • Atlas 通道压缩：R / G / B / A 四个通道各存一路序列帧（火焰 / 烟雾 / 火花 / 透明度），一张 512×512 顶四张资源
  • 压缩格式：丢弃用不到的 Alpha 通道（RGBA8 → 无 Alpha 格式），案例中 1024² RGBA 的浪费 Alpha 直接换 512² 省带宽
  • ASTC 4×4 / 6×6：按特效贴图明暗细节要求选块大小，越粗糙的烟雾越可以用大块（6×6 / 8×8）降带宽

材质指令数治理

  • 关闭 Tangent Space Normal / Subsurface / 复杂材质函数，仅保留 BaseColor / Opacity / Emissive
  • 时间动画用 Panner + Time 驱动 UV 偏移，替代逐帧 Switch 或法线动画
  • 案例参考：火焰特效 180 条指令 → 65 条，GPU 从 15ms 降到 4ms（视觉效果损失极小）

生命周期治理

  • Burst 拆 2–3 次错帧 2–3 帧，延迟子发射器约 0.1s，寿命随机化（1.0–2.0s）——平滑粒子池的"同步死亡 / 重生"尖峰
  • 远距离按距离 LOD 缩放 Spawn 数量，甚至直接关闭
  • Pooling：复用并重置 Niagara System，而非反复 Kill / Respawn

七、标杆案例深拆

标杆 A · 暗区突围：主机级动态天气在手机上的落地

GDC2022腾讯魔方UE4.26

拟真 FPS 手游，把以往只有主机才有的动态天气 + 体积云搬上手机，是「生态 / 氛围级特效」的教科书。

  • 物理大气散射：借鉴 UE SkyAtmosphere，用 LUT 减少计算量（透光度 / 多重散射 / 天空视图 / 大气透视 4 张）
  • 移动端四点取舍： ① 舍弃大气透视 LUT，改用高度雾，省 3D 纹理采样； ② LUT 全改 2D 后可用像素着色器更新（大量移动设备不支持 Compute）； ③ 利用局内时间变化慢，分帧计算每个 LUT，每帧只算少量像素，低端机也扛得住； ④ 天空视图 LUT 半八面体参数化 + 丢弃地平线以下内容，省约 50% 光线行进，GPU 从 1.35ms → 0.77ms（约省 40%）
  • 体积云：Worley 噪声 3D 纹理定义云密度，基础层 + 细节层两层噪声多次平铺，处理光在云中的多次反弹

标杆 B · 永劫无间手游：技能特效从设计到性能

雷火艺术中心网易 24UE4

动作竞技品类，技能特效既吃美术表现又吃同屏性能，是「演出型特效」的样本。

  • 万钧技能特效（特效师"老九"拆解）： 预研参考闪电侠影视表现，围绕「闪避雷电拖尾 / 雷枪 / 引雷」定质感方向； 丝滑拖尾闪电 = 材质 UV 速度 + 拖尾属性 + 法线贴图绕动流动，保证高速移动下每帧不重复； 经脉电流 = 按角色做闪电经脉模型，UV 走形实现从胸口向四肢的生长； 奥义变身三阶段（天雷引身 → 构造生长 → 雷电披风 + 双雷枪）分层演出
  • S2 性能治理：火焰特效粒子自适应剔除；宁红夜等英雄技能 / 奥义特效在不动表现前提下大幅减算；优化战斗技能计算；同屏多人时角色材质性能专项提升、关闭局外挂饰投影
  • 漫渲版（渲染层延伸）：一套时装两套画风的风格化渲染，与特效共用光照系统重制材质

标杆 C · 三角洲行动：数据驱动的生态战损特效

GDC2025天美 J3/Y1UE4 改

大世界 FPS 的「场景级特效」思路：不堆粒子，用全局数据枢纽驱动。

  • Clipmap 全局数据枢纽：植被健康度 / 四季 / 水域 / 地形湿度压缩到一张动态更新纹理，内存从约 100MB → 2.5MB，移动端才装得下
  • 燃烧 / 战损特效零变体：健康度数值区间编码在 Clipmap 通道（0.1–0.85 健康 / 四季，0.9–1 战损 / 燃烧），材质采样 LUT 做平滑燃烧过渡——不新增任何材质变体；PC 端丰富细节（烧焦树叶 / 火星），移动端简化成颜色变黑，靠材质质量分级表达
  • PCG VFX 预设：Houdini 离线生成画笔预设（落叶 / 浮尘 / 烟雾 / 雾气），移动端独立 HDA 降级配方
  • 水体特效分级：Flow Map 采样（PC 3 次 + 余弦混合，移动端高配 2 次、低配线性混合）；反射 PC 走 SSR + 多级 IBL，移动端仅 IBL

横向观察
  1. UE4 仍是移动特效主战场：11 款中 9 款 UE4 / UE4.26，UE5（王者世界 / 无限暖暖）走的是"引擎新特性换画质上限"路线，但特效落地依然靠 Niagara + 材质分级，没有脱离铁律
  2. "氛围级特效"正在替代"粒子堆砌"：暗区天气、三角洲生态、和平极清体积光——头部项目把预算花在数据驱动的全局表现上，粒子反而克制
  3. 源码级定制是常态：Mali FPK / Adreno 写带宽 / 粒子碰撞重构 / 半透明独立路径，UE 手游团队普遍改 RHI 或重写管线为特效兜底

九、避坑清单

渲染 / 性能雷区

  • 半透明多层堆叠：无论材质多便宜，堆叠后像素着色次数乘数增长——Overdraw 是特效第一杀手
  • SceneTexture:SceneColor 采样：热扭曲 / 折射反射的"性能杀手"，一处即可 60 → 30fps，改用噪声 UV 扰动伪造
  • GPU 排序 / 复杂 Vector Field 未关：fx.Niagara.AllowGPUSorting=0 按官方清单必查
  • Mask 材质 PreZ 闪烁：Prepass 与 Basepass 的 VS 编译选项不一致会导致 iOS 上部分像素无法通过 early-z 闪烁
  • Mali Depth Fetch：打掉 FPK（Early-Z），指令数异常升高，需改 GBuffer 重新编码（鸣潮坑）

流程 / 资产雷区

  • 粒子池同步死亡 / 重生：同寿命 Burst 造成的帧尖峰，拆分错帧 + 随机化寿命解决
  • 大序列帧贴图：4K Flipbook 在手机上就是发热源，Atlas 通道压缩 + 512 上限
  • 材质指令数爆表：Normal / Subsurface / 复杂函数开着不关，移动 GPU 极敏感
  • PreZ 后 Mask 与 Opaque 排序：开启 PreZ 后先 Mask 后 Opaque，depth 相同则后者覆盖前者，需显式处理
  • 用 admin / 高配机型验收特效：内测环境与真机路径不同，需用分档机型 + 正式路径验证（与"薛定谔的用户"同理）
