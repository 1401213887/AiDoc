一、核心结论速览

三层心智模型

  • 排序层：从远到近、按材质/层级
  • 混合层：Blend Equation + Src/Dst
  • 光照层：Forward 兜底 + 预烘焙数据

核心限制

  • 不能写 GBuffer → 不享受 Deferred Lighting
  • 不写深度 → 物体间排序困难
  • 移动端 Overdraw 是头号杀手

主流解法

  • 独立 Forward Pass + SH/Cubemap 间接光
  • Alpha Test 替代 Alpha Blend（草/叶）
  • Subpass 折射代替 GrabPass
总体取舍
半透明在移动端是 "画质 × 带宽 × Overdraw" 的三角博弈。本质矛盾是：Deferred 管线无法表达多层颜色叠加，所以半透明永远走 Forward 兜底。 工程上的选择本质是：能 Unlit 就 Unlit、能 Alpha Test 就 Alpha Test、能假就假——真正享受完整光照的半透明物体，全游戏可能不超过 5 类（水面、关键 VFX、玻璃、头发、布料）。

二、概念辨析（Alpha Blend / Test / OIT）

三种"半透明"实现的本质差异

类型实现机制写深度需排序移动端代价典型用途
Alpha Blend 开 BlendOp，按 Src/DstFactor 混合 否 是（按物体） 高（Overdraw + 带宽） 玻璃、水、烟、特效
Alpha Test（Cutout） discard 像素，不进入 ROP 是 否 中（破坏 EarlyZ） 树叶、栅栏、头发
Dithered Alpha 按 alpha 抖动 discard 是 否 低 LOD 过渡、远景植被
OIT (Order-Independent) Per-pixel linked list / ROV 否 否 极高（移动端罕见） 头发多层、复杂烟雾
Additive Blend One One 否 不严格 低（只读不写源色） 光效、火花、Trail
Premultiplied Alpha Blend One OneMinusSrcAlpha 否 是 中 预乘的粒子、UI
Alpha Test 在移动端 TBDR 的特殊问题
Adreno/Mali/PowerVR 都依赖 Hidden Surface Removal (HSR) / Early-Z 跳过不可见像素。Alpha Test 中的 discard 会让 GPU 必须执行 fragment shader 才能知道是否丢弃，导致：
① Early-Z 被禁用 → 被遮住的像素也跑 Shader
② HSR 失效 → 失去 TBDR 的核心优势
③ PowerVR 文档：Alpha Test 物体应"最后渲染"以减少损失
这就是为什么虽然 Alpha Test 看起来"便宜"，但**滥用比 Alpha Blend 更糟**。

Blend Mode 速查（常用 Src/Dst）

模式公式视觉效果

三、为什么 Deferred 接不住半透明

根因：GBuffer 一个像素只能存一份材质参数。 半透明的物理含义是"两份颜色按 alpha 混合"，但：

如果硬把半透明写进 GBuffer会发生什么
RT0 Albedo Blend得到"平均色"，物理上不存在的材质
RT1 Normal Blend插值法线模长不为 1，PBR 公式直接出错
RT2 Material Blend0.5 玻璃 + 0.5 墙的 Roughness 无意义
Depth 测试两难写深度挡住后面；不写深度 Lighting 找不到

BRDF 是非线性的，对"参数"做混合 ≠ 对"光照结果"做混合。所以正确顺序必须是：先把不透明物体的光照算完 → 半透明物体再在 Forward 阶段把自己的光照算完 → 用 alpha 混合"两组光照结果"。

所有 Deferred 引擎的通用解法

Step 1 · GBuffer Pass（仅不透明）

写 Albedo / Normal / Material 到 tile memory（移动）或 VRAM（PC）

Step 2 · Lighting Pass（仅不透明）

读 GBuffer，算 PBR，输出到 SceneColor

Step 3 · Sky / Atmosphere

大气和远景合成到 SceneColor

Step 4 · Translucency Forward Pass ★

半透明独立走 Forward：每个材质自己算光照（SH 间接 + 主光直算 + 可选 Forward+ 局部光），按深度排序后 alpha blend 到 SceneColor。这一步可以读 SceneColor 当背景做折射。

Step 5 · PostProcess

Bloom / Tonemap / DOF / Vignette

四、引擎机制对比（UE / Unity）

Unreal Engine 的 Translucency Mode

Lighting Mode原理移动端
Unlit不算光照，纯贴图✅ 首选，所有粒子默认
VolumetricNonDirectional采 Volumetric Lightmap（无方向）✅ 雾、烟
VolumetricDirectional带方向的体积光照⚠️ 中端机以上
VolumetricPerVertex*顶点级光照✅ 大粒子、低端机
Surface TranslucencyVolume采体积纹理 + 表面着色⚠️ 高端档
Surface ForwardShading完整 Forward，含点光阴影❌ 极贵，仅旗舰机

UE 移动端特殊机制 UE Mobile

  • Mobile HDR 关闭时：所有半透明在 LDR 下混合，省一张 R11G11B10 SceneColor
  • Translucency Sort Priority：手动指定层级避免穿插穿帮
  • Separate Translucency：半透明渲到独立 RT（开 DOF 时必须），代价 +1 张 RT
  • Mobile MSAA + Translucency：仅 4xMSAA 下可用，Adreno 实测带宽 +30%
  • r.Mobile.TranslucentDepth：开关半透明是否写 Custom Depth（粒子描边用）

Unity 的 Render Queue 与 SRP 处理

Queue 范围用途排序规则
2000~2449 (Geometry)不透明前到后（提升 Early-Z）
2450 (AlphaTest)Cutout前到后
2500~2999 (Transparent)半透明后到前
3000+ (Overlay)UI、Lens Flare按 Queue

Unity URP/HDRP 半透明专属机制 Unity

  • URP Forward+：半透明可接受 32 个 / tile 的点光（2022+）
  • HDRP Stacked Lit：双层材质堆叠（车漆/眼睛），本质是手动 OIT
  • Single Pass Forward Lighting：URP 半透明默认走单 Pass，多光照只走主光 + 4 个非重要光
  • Light Probe Proxy Volume (LPPV)：大半透明物体（如云、玻璃幕墙）按格子采 SH，避免整物体一个 SH 的"光斑"问题
  • Soft Particles：URP 内置，按深度做边缘软化，避免粒子穿插穿帮

Vulkan / Metal Subpass 的特殊机会

Subpass Self-Dependency · 燕云/原神在用
Vulkan 1.0+ 提供 VkSubpassDependency with VK_DEPENDENCY_BY_REGION_BIT，允许同一个 Subpass 内 读自己当前 tile 的 SceneColor。这相当于 OpenGL ES 的 GL_EXT_shader_framebuffer_fetch。

用途：半透明 shader 可以读 Lighting 阶段写入的 SceneColor 作为背景做折射/扭曲，完全不需要打断 RenderPass、不需要 STORE 到主存。Adreno 740 上典型节省 8~12% 主存带宽。

五、半透明的七档光照方案

从最便宜到最贵

档 1 · Unlit + 顶点色 / 流光贴图

完全不算光照，亮度烘焙到顶点或贴图。所有粒子默认。

  • 代表用法：剑光 Trail、UI、Add 粒子、远景烟雾
  • 成本：≈ 0

档 2 · Half-Lambert + 主光

NdotL · 0.5 + 0.5 让背光面也有底亮度，常配 SSS 近似让树叶背光透出绿色。

  • 代表用法：草、树叶、雨雪粒子、半透明布料
  • SSS 近似：pow(saturate(-NdotL), 2) * SSS_Tint

档 3 · Light Probe / SH 间接光（标配）

采样 9 个 SH 系数得到环境光，每个物体一次采样。

  • Unity: ShadeSH9(worldNormal) / URP: SampleSH(N)
  • UE: GetSkySHDiffuse + Indirect Lighting Cache
  • 大物体用 LPPV 或 Tetrahedral Tessellation 避免"一物一光"

档 4 · Reflection Probe / Cubemap 反射

镜面分量用预烘焙 Cubemap，按 Roughness 采不同 Mip。

  • Box Projection 解决"反射不对位"
  • 移动端水面、玻璃、湿地面的主力方案
  • 燕云水面 = Gerstner 波 + Cubemap，没有 SSR

档 5 · Forward+ / Tile Light List

Compute 算每 tile 的光列表，半透明 shader 查询循环。

  • Unity URP Forward+（2022+）/ UE5 Mobile Forward+
  • 原神高档、星铁、绝区零的角色用这条路
  • 代价：Light Culling Compute Pass +0.3~0.8ms（Adreno 740）

档 6 · 折射（Sample SceneColor）

半透明 shader 采样背后的 SceneColor 模拟玻璃折射、水下扭曲。

  • 桌面：GrabPass / SceneColor Texture（需 STORE + LOAD）
  • 移动端推荐：Subpass Self-Dependency 或 framebuffer_fetch
  • UE: SceneTexture: PostProcessInput0 在 Translucency 阶段可用

档 7 · Volumetric / 体积光照

沿视线 Ray March 累加光照，或填充 Froxel Volume。

  • 移动端几乎不上真 Ray March，多用 2D 贴图近似 + Sky LUT
  • 原神/星铁的体积雾走 Froxel 简化版（高档）
  • 燕云体积云 = 贴图 + Noise，PC 才上 Ray March

六、移动端 TBDR 专属优化

核心矛盾：半透明 = Overdraw + 带宽

问题原因对策
Overdraw 爆炸 多层半透明叠加，每层都要采贴图 + 算光照 美术控层级；远景粒子合批；按距离剔除
带宽往返 每个半透明像素都要 Read+Modify+Write SceneColor R11G11B10 替代 RGBA16F；保持 Subpass 完整
Alpha Test 杀 EarlyZ discard 让 HSR 失效 Cutout 物体后渲；远景换 Dithered；不要乱用 discard
排序穿插 按物体排序无法解决"两个长粒子互穿" 按 Particle Pivot 重心 / 按面片中心 / 限制粒子大小
UI 与场景半透叠加 UI 走独立 RT 还是合到 SceneColor 各有代价 常规：UI 独立 RT + 最终 Composite；MMO：UI 直叠

关键优化技巧

1. Soft Particle（深度软化）

粒子接触地面时根据 SceneDepth - ParticleDepth 衰减 alpha，避免硬边。

  • 代价：需要采样 Depth → Subpass 中断风险
  • 移动端最好用 已 STORE 的 EarlyZ Depth，不要为此打断 Subpass 链

2. 粒子顶点光照

大粒子（如烟雾）主光算到顶点，fragment shader 仅做插值。可省 70~85% ALU。

3. 粒子合批（Particle Atlas）

所有粒子贴图烘到一张 2K Atlas，按 UV Flipbook 索引，整局 1 个 Draw Call。

4. Pre-Multiplied Alpha

finalColor.rgb *= alpha 烘到贴图。混合时 Blend One OneMinusSrcAlpha。
好处：解决"半透明边缘溢色"，多层混合精度更高。

5. Dithered Alpha（替代 Alpha Blend）

远景植被、LOD 切换、Camera Fade 用蓝噪声抖动 + discard 代替真半透明：

  • 不需要排序
  • 仍然 break Early-Z，但对远景影响小
  • 配合 TAA 可消除颗粒感（移动端少数旗舰才开 TAA）

6. Translucent Light Volume

UE 提供的预计算"半透明专用光照体积"，48×24×48 网格存光照，每帧更新一次。
半透明物体采 3D 纹理 → 1 次采样得到当帧的局部光照，不用走 Forward+。

观察
几乎所有头部手游在战斗特效上无脑用 Additive——加法天然不需要严格排序（满足交换律），ROP 又不需要读 Dst Alpha。真正需要"看见后面"的半透明（玻璃、水、烟）才走完整 Forward 兜底。

八、避坑清单

排序穿帮

  • 两个长条粒子互穿：按 Pivot 排序无法解决，需用 BillboardChain 或 GPU 排序
  • 粒子和水面互穿：手动指定 Render Queue 偏移
  • UI 在场景半透明前面：UI 必须最后渲

Subpass 链断裂

  • 半透明读 SceneDepth 软化时，若 Depth 未 STORE，会强制 RenderPass 断裂
  • 解决：用 EarlyZ Depth Prepass + 显式 STORE
  • Adreno 实测：断一次 RenderPass 损失 0.5~1.5ms

Overdraw 失控

  • 战斗高峰一个像素被 30+ 个粒子覆盖
  • 对策：粒子距离剔除、合批、限制最大并发数
  • 关键 KPI：Translucency Overdraw（UE Visualizer 可查）

Alpha Test 滥用

  • 把所有"边缘"问题都用 Alpha Test 解决 → HSR 全失效
  • 叶子/草 OK，但不要把 UI 字体、玻璃边缘做成 Cutout
  • PowerVR/Mali：Cutout 物体应单独排到不透明组的最后

移动端 OIT 不要碰

  • ROV (Rasterizer Ordered Views) 移动端不支持
  • Per-pixel linked list 需要原子操作，Mali/Adreno 慢且不稳
  • 头发想要 OIT 效果 → 用 Hair Card + Pre-Sorted Strands

带宽误判

  • SceneColor RGBA16F 看起来"只多 4 byte/px"，但半透明 Read+Write → 实际带宽 ×4
  • R11G11B10 在移动端是强制选择，除非有明确 HDR Bloom 需求

分档配置不齐

  • 高档开 Volumetric Fog，低档忘了关 → 中端机直接卡帧
  • SSR/SSAO 也要按档关闭半透明的读取

"假"半透明真香

  • 玻璃窗 → 贴 Cubemap + Fresnel，不开 Blend
  • 水面远景 → 直接 Alpha Test + Noise，不做折射
  • 能假就假，每多一个真半透明物体都是带宽税

九、落地 Checklist 与定位工具

施策优先级（从便宜到贵）

  1. 看效果能不能 Unlit → 90% 粒子都能
  2. 能不能 Additive → 不需要排序，最便宜
  3. 能不能 Alpha Test + Dithered → 不破 EarlyZ 太多
  4. 能不能 SH 间接光 + 主光直算 → 标配中档
  5. 能不能 Cubemap 反射代替 SSR → 玻璃水面通用
  6. 能不能 Subpass 折射代替 GrabPass → 移动端必选
  7. 实在不行才上 Forward+ Tile Light List → 仅角色/水面
