四、关键发现与根因

① 体积云延迟着色 PS —— 单次最重，寄存器型瓶颈（P0）

SceneColorRendering > DeferredShading > MP_Map_1.BP_ParentCommonEnvLight1_Cloud (eid=3796)
单个 Draw 吃掉 1.435ms / 全帧 21.8%，是当之无愧的头号热点。AOC：Overall GPR=44（偏高），导致 ALU fiber occupancy 仅 25%，并发 wave 不足；exposed long latency 45.6%——近半周期卡在等访存且无 wave 可掩盖。这是典型的 高 GPR → 低 occupancy → 延迟暴露 因果链，属寄存器压力型。指令总量 24875、32-bit ALU 占 7987（half 仅 17%）也偏重。
  • 降 GPR：拆分 shader、缩短中间变量 live range、避免大本地数组/动态索引。GPR 从 44 降到 ~32 即可显著抬升 occupancy。
  • half 化：把云的散射/积分等 full-precision 计算尽量改 half，既减 ALU 周期又降寄存器。
  • 降步进/采样数或用更激进的体积分级，直接削减 in-flight 纹理采样占用。

② 软阴影投影 PS —— 第二热点，访存/依赖链型瓶颈（P0，根因不同于①）

ShadowProjection > RenderMobileShadowProjections > MMH > MMH::ShadowMapProjection (eid=2324)
单 Draw 0.832ms / 12.6%。AOC 呈现与①完全相反的画像：GPR 仅 12、occupancy 已拉满 100%，但 exposed long latency 仍高达 50.1%。并发已无提升空间，延迟依然掩盖不住 → 这是访存/依赖链 bound，而非寄存器问题（shader 含 DAG 结构遍历 + 页表查询 + SMRT 光线步进，访存链很长）。
  • 减少纹理/内存访问次数，提升访存局部性（page table / physical texture 命中）。
  • 缩短 load→use 依赖链，让相邻采样可并行发射。
  • 注意：此处提 occupancy 无效（已 100%），别往降 GPR 方向使劲。

③ BasePass + DepthPrepass —— 高频小 Draw，吞吐型（P1）

SceneColorRendering > MobileBasePass (222 Draw, 0.798ms) ＋ FullDepthPrepass > MobileRenderPrePass (204 Draw, 0.679ms)
合计 426 个 Draw、1.477ms / 22.4%。这与①②性质不同：单个 material shader 大多健康，瓶颈在 Draw 数量 / 吞吐（绑定切换、顶点/三角形提交、overdraw）。优化抓手是合批与剔除，而非单 shader 调优。
  • 合并 draw（instancing / 静态合批）、减少材质与状态切换。
  • DepthPrepass 已在，确认 BasePass 充分受益于 early-Z；压制 overdraw。

④ 后处理与 GTAO 链路健康

TAA PS（eid=4105）AOC 健康：GPR=13、occupancy=87%、exposed long lat 33%。GTAO HorizonSearch PS（eid=2279）同样健康：GPR=14、occupancy=75%、exposed long lat 仅 19.1%、half 占比已达 38%（ALU 16-bit=345）。两者均无需优化。
