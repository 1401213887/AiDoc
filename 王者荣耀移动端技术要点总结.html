一、核心结论速览

渲染策略

  • 典型 前向渲染，俯视固定相机利好 frustum 剔除
  • 主光（方向光）+ 局部点光，通常 1~2 实时光
  • 极少屏幕空间后处理，仅 Bloom/Tonemap 视档位开关

资产策略

  • 英雄统一 1 套 BaseColor + Mask（高低端共用）
  • 地图大量使用 烘焙 Lightmap，节省运行时光照
  • 静态场景 Atlas + Mesh Instancing（草丛/树/装饰）

机型预算

  • 低端档：30~40 fps，540P，关阴影/Bloom
  • 中端档：60 fps，720P，1 级 CSM
  • 高帧档：120 fps，1080P，全开特效
总体取舍
王者最大的特点不是画质上限，而是 画质下限——必须在 2014 年的低端机上还能跑 30 fps。这决定了它的所有技术决策都围绕"分级降级路径"展开：从同一份美术资产派生出 6+ 个画质档位，而不是用一个固定中档去强制玩家硬件升级。

二、机型分级与画质档位

三、渲染管线与 Pass 结构

Pass 1 · ShadowMap（中档及以上）

1 级 CSM，分辨率 512² 或 1024²，仅角色 + 重要场景投影。低端档完全跳过，用 Blob Shadow（贴在地面的圆形 alpha 贴图）模拟。

Pass 2 · Opaque BasePass（前向）

地形 → 场景静态 → 英雄。所有不透明物体一次写入 SceneColor + DepthStencil。Lightmap 直接采样，无需 GBuffer。

Pass 3 · Transparent

技能特效、烟雾、UI 前的粒子。按 距相机距离排序，使用 Soft Particle（中档以上）或硬边（低档）。

Pass 4 · 后处理（条件）

Bloom（中档）→ Color Grading（高档）→ Vignette（极高档）。所有后处理都做成 可单独 toggle 的子模块。

Pass 5 · UI

UGUI/UE-Slate 风格的 UI Batch，在 SceneColor 之上叠加。MOBA UI 占屏比例高，通常会单独跑一次绘制以避免与 3D 重叠的 overdraw。

四、资产规格与共享策略

英雄

  • 面数：默认 6000~9000 三角形；皮肤可达 12000；勇者级以上有专属 Bone Count 上限
  • 贴图：BaseColor 1024² + Mask(R:Metallic G:Smoothness B:AO A:Emissive) 1024²
  • 骨骼：典型 60~80 根；面部表情骨骼 vs Blend Shape 视皮肤档次切换

地图

  • 整张地图 静态烘焙，Lightmap 4096² 拆为 4 张 2048² 区块
  • 植被：Mesh Instance + GPU Instancing，单批可绘制 200~500 棵
  • 水面：低档为静态法线贴图 + Specular，高档为屏幕空间扰动

五、英雄角色渲染

王者英雄渲染的核心目标：俯视角下还能看出脸/服装质感，但不需要电影级 PBR。

  • Half-PBR：Mask 通道塞 Metallic/Smoothness/AO/Emissive 4 项
  • 没有 Subsurface（皮肤次表面），用 Rim Light 边缘光增强角色立体感
  • 布料/披风：Vertex 偏移做风动，无 Cloth 模拟
  • 头发：双层透明 + Anisotropic 高光近似（高档），低档退化为不透明 + 法线贴图

六、光照与阴影

静态光照

  • 主光为方向光（太阳），Lightmap 烘焙
  • 使用 Unity 的 Progressive Lightmapper / Bakery
  • 烘焙范围：整张地图 + 所有静态道具

动态光照

  • 角色用 Light Probe 网格（约 1m 间距）做间接光
  • 实时主光仅 1 盏（方向光）
  • 技能/buff 自发光不进入 Shadow 计算，纯 Emissive

阴影方案

  • Blob Shadow：低档，贴地圆形 alpha
  • Planar Shadow：英雄投影到平面，矩阵投影
  • CSM 1 级：中高档，仅一层 1024²

反射

  • 无 SSR；使用 1 张 Cubemap 做环境反射
  • 水面用顶视投影 + 简化 Cubemap

七、技能特效与后处理

特效预算
MOBA 团战时同时存在的技能特效可达 20+ 个。粒子总数控制在 8000 以下，采用 LOD 距离剔除 + 视野外完全停摆。
  • Mesh Particle：能量护盾、刀光、地表魔法阵——优先用单 Mesh + 顶点动画，避免大量粒子
  • Trail：带 Soft Particle，限制最大 16 段
  • 屏幕空间扭曲（仅高档）：Cloak/隐身/爆炸冲击波，需要 SceneColor copy，是中端档关掉的主要原因
  • 无烟雾体积光，用 Mesh + 假体积贴图代替

八、长线优化与兼容性策略

Shader 变体爆炸控制

10 年长线运营，shader 变体可达数千。王者的策略：

  • Material LOD：远距离切换到极简 shader（无 normal、无 specular）
  • 变体白名单：每次发版前打 shader 变体 dump，超过阈值的合入需技术评审
  • Warmup：进入战斗前预热常见 shader 组合，避免战中 hitch

启动与战斗加载

  • 地图资源 AB 化，开战前已下载，进入战场仅做 Asset Load + Shader Warmup
  • 英雄资源 LRU 缓存，常用 Top 50 英雄常驻内存
  • 战斗内 GC 控制：所有 frame allocator/pool 全部预分配，战斗中不允许 new 大对象

发热降频应对

  • 5 分钟后自动 降低渲染分辨率（Dynamic Resolution Scale）
  • 高帧档位会监测温度，超过 45° 自动降到 60 fps
  • UI 动画在低帧档关闭背景 motion，省 GPU

九、关键启示

对 PVP/竞技手游的启示

  1. 俯视角是压低开销的天然优势——剔除好做、阴影简单、远景小
  2. "画质下限"决定用户基数，不要为了几台旗舰机牺牲 80% 玩家体验
  3. 分级要从美术阶段就介入，不能等运行时再降级

对长线运营游戏的启示

  1. Shader 变体必须治理，否则 build 时间和包体会指数膨胀
  2. 新皮肤是技术升级的载体，但底层 shader 不能跟着升
  3. 战斗内 GC 是 60→120 fps 的最大坎，越早做对象池越省事
