二、压缩 vs 无压缩分布

关键概念：块压缩（ASTC）只能用于"被采样的美术资产"；渲染中间靶（RT/GBuffer/深度/HDR 等）GPU 必须以无压缩线性格式读写，不可能也不应该压缩。因此"无压缩"里绝大多数是合理的 RT，真正需要审查"该压未压"的只有采样资产那一类。

统计口径（已升级为遍历采样）：本节不再只看 RenderPass 输出，而是遍历 BasePass 多个不同材质的 Draw（e2420/2441/2507/2862/3242）+ 角色 + UI，逐个提取其输入贴图并 get_texture_info 实测，去重得 31 张资产纹理。分三类：① 采样美术资产（应压缩）② 渲染中间靶 RT（应无压缩）③ 数据/ramp/LUT 小图（按需）。全量 540 张仍需 UE listtextures 完整核对。

七、贴图性能风险分析（对照热门手游资产规范）

规范基线参考：移动端商业手游（原神/崩坏:星穹铁道/王者荣耀级）通用纹理规范——安卓统一 ASTC、所有采样纹理带 mip、HDR 中间靶慎用 RGBA16F、移动端慎用 3D 体纹理。

良好分辨率与压缩规范合格 — 场景 512² / 角色 1024² / 全 ASTC 6×6

遍历 BasePass 多材质 Draw 实测：场景材质压倒性为 512²（占采样资产 68%）、角色 1024²、无超尺寸贴图，对照商业手游规范属规范甚至偏保守配置。采样资产 30/31 已 ASTC 压缩（块清一色 6×6）；唯一未压缩的 CA_PaleWall(256×10 RGBA16F) 是 ramp 查找表，不压缩是正确的（条状数值纹理压缩会破坏插值精度）。

高LuxGI 3D 体纹理 — 移动端带宽 + cache 杀手

LuxGI 动态 GI 绑定 3 张 3D 体纹理（Mip1SHTexture RGBA16F 40×40×96、IndirectionTex R32_UINT 32³、IrradiancePage 1024²）。3D trilinear 采样在移动 GPU cache 极不友好，每像素在 DeferredShading uber PS 中采样 → 已被真机 SDP 实测确认为带宽大头之一。规范上移动端应慎用 3D 体纹理。

中TAA History 使用 RGBA16F（8 字节/像素，全屏每帧读写）

TAA.History 为全分辨率 RGBA16F，是全屏纹理里单像素字节最高者。TAA 历史常用 16F 保精度，但在低端机上每帧读+写翻倍带宽。可评估降到 R11G11B10 / RGB10A2，省约一半 history 带宽。

中全分辨率中间靶偏多（约 11 张 1016×504）

Depth/GBufferA/B/C/SceneColor/Velocity/History/ShadowMask/ToonOutline/CharFeature 等均为全分辨率。叠加后单帧片上+主存压力大，且与 TBDR tile 预算相关（GBuffer 总字节若超预算会触发缩 tile / 多 bin）。建议核算 tile 预算并考虑半分辨率化部分靶（如 ToonOutline/CharFeature）。

良好美术资产格式规范 — ASTC + 完整 mip 链

抽样到的角色/场景资产均为 ASTC（SRGB 基础色 / UNORM 法线遮罩），且带完整 mip（1024² 11mip、512² 10mip 等）。SlateUI 走 Virtual Texture（6072² 物理页 + 页表），符合大世界 UI/材质的虚拟纹理规范。这部分符合商业手游标准。

良好光照/剔除数据用紧凑整型小图

Forward+ 光照网格用 R32_UINT 的 1024×5 / 1024×17 小图，HZB 用 R16F，AO 用 R8 半分辨率——数据型纹理格式选择紧凑合理，无浪费。

八、优化方向（按收益排序）

  • P0 · LuxGI 体纹理降负载：3D 体纹理降分辨率 / SH 数据压缩 / GI 半分辨率着色 + 双边上采样。直接命中 SDP 实测的带宽大头，对低端机收益最大。
  • P0 · 拆 DeferredShading shader permutation：缩小指令 footprint 缓解 I-Cache Miss，并让无 GI 像素跳过 3D 采样。
  • P1 · ASTC 压缩档按用途分级（当前一刀切 6×6）：数据型贴图(roughness/AO/mask)降到 8×8 再省 ~44% 体积与采样带宽；角色关键法线若有块状光照瑕疵则升 5×5。建立 UE Texture Group 分级规则，替代全局默认 6×6。
  • P1 · TAA History 降格式：低端机上 RGBA16F → R11G11B10 / RGB10A2，省一半 history 带宽，A/B 验证画质损失。
  • P1 · 全屏中间靶瘦身：ToonOutline / CharFeature 等评估半分辨率化；核算 GBuffer 总字节是否超目标机 tile 预算。
  • P2 · 角色 Toon 调色进 LUT：BasePass Toon PS 的 ACES 色域矩阵 + 色相偏移可预计算进 LUT，省逐像素矩阵乘/Atan2/Pow。
  • P3 · 全量资产合规普查：用 UE listtextures / Asset Audit 导出全部 540 张的格式/尺寸/显存，查未压缩大图、缺 mip、超尺寸——本报告无法覆盖的 504 张资产纹理需此手段确认。
