一、核心结论速览

渲染策略

  • UE4 Mobile Forward 改造
  • 近战为主，相机距角色近 → 角色精度优先
  • 大逃杀 60 人同屏，但实际可见多在 6~10 人

核心技术

  • 角色：PBR + Anisotropic 头发/披风/金属
  • 地图：UE Landscape + 大量 HLOD
  • 飞索系统是核心玩法，需稳定的角色姿态融合

预算/Format

  • SceneColor R11G11B10
  • Shadow 2 级 CSM
  • 动态分辨率 720~1080P
永劫手游的工程定位
端版是 PC 大逃杀，平台跨度从 PC i7+RTX 一路到手机 SD 7+。永劫手游需要在保持端版"近战感"和"飞索流畅度" 的前提下，把端版的资产和玩法做大幅减负。

二、端转手的工程难点

端版特性手游处理
2K 贴图、20k 角色三角形压缩到 1K 贴图、8~12k 三角形
SSR/SSAO/体积雾全开移动端默认关，仅高档恢复部分
地图 8km × 8km缩减到 6km × 6km，保留核心区域
动作系统 100+ 动捕动作动作池压缩，远距离用 LOD 动画
实时反射Cubemap + 关键水面 SSR（高档）
动态 GILight Probe + 烘焙 Lightmap

三、Pass 顺序与 RT

Pass 1 · ShadowMap

2 级 CSM，1024²。仅角色 + 大型建筑投影。

Pass 2 · Depth Prepass

角色 + 重要场景，便于后续 Soft Particle / Decal Z-test。

Pass 3 · BasePass（Forward）

地形 → 植被 → 建筑 → 装饰 → 玩家角色 → 敌人。Lightmap 直接采样，无 GBuffer。

Pass 4 · Sky / Atmosphere

大气散射 LUT + 体积云贴图近似。

Pass 5 · Translucency

水、雾、技能特效。命中爆点的屏幕扭曲在此 Pass。

Pass 6 · UI

大逃杀 UI 量大（地图、技能、装备、伤害飘字），单独优化批处理。

Pass 7 · PostProcess

Bloom + Tonemap + 色调（武侠风偏暖偏对比）。

四、大逃杀地图与 streaming

UE Landscape + HLOD

  • UE Landscape Heightmap，多层 Splat 地形
  • HLOD 整合远景区域为单 Mesh + Atlas
  • 移动端启用 RVT（Runtime Virtual Texture）做地形 Decal
  • 玩家"开镜瞄远处"是常见场景，需要远景 LOD 不能塌陷太厉害

建筑与 POI（兴趣点）

  • 古风寺庙、村庄、山洞，约 20+ 个 POI
  • POI 内部用 Light Probe 模拟间接光
  • 跨 POI 的烟囱、塔楼用 HLOD 远景模型

植被

  • 近：Mesh Instancing
  • 中：LOD
  • 远：Imposter
  • 风场扰动：CPU 高度 + Vertex 偏移

五、武侠角色 PBR

  • 角色用 标准 PBR，不是 NPR
  • BaseColor 1024² + Mask（R Metallic G Roughness B AO A Emissive）
  • 布料披风：实时物理（PhysX Cloth 或 UE Chaos Cloth）
  • 头发：Anisotropic 高光 + 多层透明
  • 面部：法线贴图 + 简化 SSS（用屏幕空间模糊近似）

武器

  • 武器贴图独立，金属质感重要
  • 武器轨迹 Trail 是核心战斗反馈
  • 命中瞬间触发 Camera Shake + 屏幕扭曲

六、近战连招与飞索

近战 + 飞索的渲染挑战
飞索玩法导致玩家高速移动 + 镜头大幅旋转。这要求：① 动态 streaming 不能 hitch；② 动作过渡稳定；③ 动态分辨率响应快。

近战

  • 精准的命中判定 + 招式 Trail
  • 架招/格挡：Hit Stop（短暂时间停止）+ 屏幕震动
  • 处决：切相机 + DOF 虚化背景，类似过场动画

飞索

  • 飞索是 Spline + 动画驱动，渲染层不复杂
  • 飞索期间相机模糊轻微（Motion Blur 可选）
  • 同屏多人飞索时需要严格控制特效预算

七、网络同步与画面一致性

  • 大逃杀 60 玩家，服务器位置广播 + 客户端预测
  • 动作同步：动画状态机 + 关键帧广播，远端玩家用 LOD 动画
  • 渲染层做 客户端预渲染：技能播放始于本地，等待服务器确认
  • 命中反馈：本地预测命中 + 屏幕特效，服务器修正后回滚（rare）

八、移动端性能策略

分档

  • 低/中/高/极高，旗舰机推 60/120 fps
  • 低档：720P + 关 SSAO/SSR/体积云 + 远距离玩家用低 LOD 动画
  • 极高：1080P + Bloom + 部分 SSR + 60 fps

大逃杀专项优化

  • 同屏 60 玩家但可视化通常 ≤10，远距离玩家用 极简 Skinning + 简化 Material
  • 玩家阵亡瞬间释放角色资源（不缓存），节省内存
  • 武器/装备资源按"区域可见"加载，落地后才完整渲染

UI 优化

  • 大量 HUD（技能、地图、队友、装备、伤害飘字）
  • 使用 UE UMG，但批处理优化大量定制
  • 玩家头顶名字/血条用单一 Drawcall 绘制（GPU Quad 集合）

发热降频

  • 5 分钟后 DRS 降分辨率
  • 高温时关闭 Bloom 或降级
  • 极端时降帧（120→60）

九、关键启示

对端转手项目

  1. 美术资产必须重做，不能直接降分辨率
  2. 地图缩放和 POI 取舍要早做决策
  3. 动作系统是端转手最容易"塌"的环节，要保留核心动捕

对大逃杀手游

  1. 60 玩家同屏的关键是"远距离玩家极简化"
  2. UI 渲染开销不容忽视，需要专项优化
  3. 客户端预测 + 服务器修正是网络同步的标配
