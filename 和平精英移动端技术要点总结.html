一、核心结论速览

渲染策略

  • Forward 渲染，光源单一
  • 实时 CSM（2 级）+ Lightmass 烘焙
  • Early-Z 针对 Masked 植被
  • 双层地形：远景一张 Mesh + 近景 Landscape

资产策略

  • HLOD 烘焙覆盖所有静态物
  • 建筑贴图集中在1 张 Atlas
  • 植被 Atlas + Billboard 化
  • PBR-Lite：5 张图压缩为 1 张

性能基线（截帧实测）

  • Drawcall 稳定 < 300
  • Overdraw < 3.0×
  • 纹理显存 ≈ 5.3 MB / 帧
  • 面片 ~28 万 / 顶点 ~88 万
总体取舍
和平精英是"硬抠传统优化"的标杆：UE4 移动端通用版功能 → 砍/合/烘焙 → 把面数、Drawcall、贴图量、内存全部压到能在 1GB RAM 设备上跑。没有花哨的新管线，但每一项细节都打磨到位。

二、引擎选型与定制

核心挑战
立项时市面上几乎没有手游用 UE4，更没人在手机上做过 8×8 km 写实大地图，光子团队只能"开荒式"对引擎做大刀阔斧改造。

渲染效果增强方向

  • 光照（Lighting）
  • 阴影（Shadow + Shadow Cache）
  • 后处理（Post-processing）
  • 平面反射（Planar Reflection）
  • 体积雾（Volumetric Fog）

性能优化方向

  • 动态合批（Dynamic Batching）
  • 带宽优化
  • 地形系统优化
  • RHI 层重写
  • 阴影 Cache
  • Early-Z 应用

四、阴影方案（CSM + Lightmass）

实时阴影 — 2 级 CSM

  • 覆盖角色 + 附近一定范围物体
  • ✅ 投影：建筑、高大树木、角色
  • ❌ 不投影：马路、山体岩石、低矮灌木、杂草
  • 策略：严控参与 ShadowMap 生成的物体范围

烘焙阴影 — Lightmass

  • 主要用于建筑室内
  • 配套 Lightmap + Normal Map
  • 实时 + 烘焙混合融合
关键 trick
"可见且贡献明显才投影" —— 把投影白名单做到尽可能小，是手游阴影性能控制的核心思路。三角洲的"3 级 CSM 远景仅大型物体"和这里的"马路/灌木不投影"是同一种哲学。

五、植被渲染系统

  • 基础技术硬件 Instancing + LOD
  • 组织方式Cluster 分组管理
  • 同屏峰值1193 个植被实例（Drawcall 281）
  • 远景植被1–2 个面片 Billboard
  • 屏占比高最多 ~2478 面 / 实例
  • 面数控制实例数 × 单株面片 ≈ 常数（如 600 × 4 ≈ 2400）

贴图优化

策略实现
树叶 + 树干合并同一张贴图，避免 2 次 DC
杂草类合并多种植被共用 Atlas
过渡优化地表 Layer 颜色与植被颜色相近，掩盖 Culling 边界

六、Culling 多层剔除

4 类剔除算法堆叠

  1. Distance Culling — 距离剔除
  2. View Frustum Culling — 视锥体剔除
  3. Precomputed Visibility Volumes — 预计算可见性体积
  4. Dynamic Occlusion Culling — 动态遮挡剔除

遮挡剔除实测

  • 有遮挡视角DC = 181
  • 无遮挡视角DC = 216
  • 差异~16% 来自 Occlusion Culling

七、地形系统（双层架构）

第一层 · 远距离地形 Mesh

52,560 顶点 17,520 面 仅 1 个 Drawcall

整张地图就是一张 Mesh，配 Color + Normal + 烘焙 Shadowmap，覆盖整个 8×8 km。飞机跳伞俯瞰阶段就是它在出力。

第二层 · 近距离 Landscape 系统

UE4 原生 Landscape VS 阶段动态生成网格 内存比 Static Mesh 节省 6–7×
  • 地形数据编码到 Texture，VS 实时采样建网格
  • Texture Mipmap 天然支持 LOD
  • 同 LOD 级别的地形块走 Instancing 合批
公路设计
使用 Spline Tools，自动修改 Landscape Heightmap 适配 Spline 形状 —— 公路与地形无缝衔接，不需要单独的路面 Mesh。
📌 与三角洲对比：三角洲走得更远，把路面直接画进地形材质层，连 Heightmap 修改都省了。

八、静态物体 + HLOD

近距离

  • 独立 Mesh 渲染
  • 相同 Static Mesh 走 Instancing

远距离 · HLOD

  • ≥ 2 级 LOD
  • 启用合并贴图选项

九、Early Z-Pass 优化

问题：Masked 材质（带 AlphaTest 的植被）会破坏硬件 Early-Z 早期剔除。

解决：Masked 植被在同一帧内绘制 2 次：

  1. 第一次：Early Z-Pass，仅写深度
  2. 第二次：Basepass 着色，硬件已经能从深度图提前 reject 被遮挡像素

代价：植被几何提交两次（多一些 Vertex Shader 开销）
收益：Pixel Shader 调用大幅减少，Fragment 阶段压力下降

📌 配置入口：Project Settings → Engine → Rendering → Optimizations

十、PBR-Lite 材质系统（地图专属材质）

问题背景
传统 PBR 一份材质要 5 张图（BaseColor / Normal / Roughness / Metallic / AO），每张 1024² 大约 4MB，5 张 = 20MB；一张地图上万个物体，存储和带宽完全顶不住。

解决方案：智能纹理贴图

原始 5 张图 (1024² × 5 = 20 MB)
   ↓ 合并压缩
1 张智能纹理贴图 (1024² × 1 = 4 MB，压缩率 80%)

通道布局：
  R   = BaseColor.R
  G   = BaseColor.G
  B   = BaseColor.B
  A   = Roughness + Metallic + AO 的混合编码
        ← Shader 端用算法快速分离三者

📊 PBR-Lite 智能纹理可视化（5 张压 1 张）

动态 LOD 材质切换（按距离档位）

距离档位材质策略视觉表现
≤ 10 m高清智能纹理 + 法线贴图看得清锈迹、纹路细节
10 – 50 m中清智能纹理（去法线）基础形状 + 颜色
≥ 50 m低清智能纹理 + 物体合并仅显示轮廓
和三角洲对比
三角洲走的是 "通道复用"（Normal 贴图 4 通道塞 Mask + 法线 + Roughness）；和平精英走的是 "5 张合 1 张"。本质都是减少纹理 IO，但和平精英压得更狠（A 通道塞 3 个值）。

十一、内存优化（三层下钻）

Gameplay 层

游戏对象生命周期、Tick 频率、缓存策略 —— 把 UE 默认的"Actor 满天飞"降到合理量级。

Engine 层

纹理 Streaming、Mesh Cache、Asset 引用计数、各模块内存占用画像 —— 找出 UE4 通用版的内存大户逐一优化。

Native 层

容器分配器、对象池、RHI 资源生命周期 —— 跨过 UObject 反射层做 C++ 原生优化。

这层的难度
UE4 通用版跑手游内存就是不够 —— 团队等于把 UE4 内存系统从顶到底拆了一遍重新调，是项目最重的攻坚之一。

十二、Lite 版超低配适配

目标设备

  • 运行内存1 GB
  • 图形 APIGLES 2.0
  • 市场东南亚低配机型

策略

  • 玩法一致：基础游戏指标与标准版保持一致
  • 独立分支：中台 + 项目联合深度定制研发
  • 渲染降级：极致砍材质、关动效、降分辨率
为什么这事值得讲
GLES 2.0 + 1GB RAM 几乎是手机能跑 3D 游戏的物理下限。能让一个 8×8 km 的开放世界在这种机器上跑起来，是工程能力的极限秀。

十三、关键启示与可借鉴方向

① 小光源场景 → Forward 是正解

战术竞技基本是户外 1 主光，Forward 在带宽和功耗上完胜延迟，没必要硬上 Mobile Deferred。
启示：管线选型先看光源数量，不要被"先进 = 延迟"的迷思绑架。

② Drawcall < 300、Overdraw < 3× 是健康线

开放世界 FPS 在中端手机上想稳，这两个数字基本可以当 KPI。
启示：在引擎层做 stat 监控，超线立即报警。

③ 双层地形是"性能 + 视野"的标准答卷

1 张 Mesh 远景 + Landscape 近景 = 跳伞俯瞰也能看见全图、地面跑动也有细节。
启示：跳伞类视野极广的游戏，远景一定要单独一张极简 Mesh。

④ Early-Z + Masked 植被的"画两遍" trick

多一次 VS 提交，换 Fragment 阶段大幅减负，对植被密集场景是一笔好买卖。
启示：所有 AlphaTest 的密集物体都值得开 Early-Z。

⑤ PBR-Lite 把 5 张贴图压成 1 张

RGB = BaseColor，A = Roughness/Metallic/AO 混合编码，Shader 端解码。
启示：Tile-based GPU 的纹理带宽是大头，"少 1 张图比省 100 个 Drawcall 还值钱"。

⑥ HLOD + 全场景共用 Atlas

所有静态物 HLOD 烘焙、所有建筑贴图集中 1 张 Atlas，远景几乎零代价。
启示：开放世界开发期就要把 HLOD 流程纳入构建管线，不要做完了再补。

⑦ 内存优化必须穿透三层

Gameplay → Engine → Native 全链路，UE4 通用版的内存模型在手游上必须重做。
启示：内存预算超标时，逐层 dump 找大户，不要只优化最上层。

⑧ 海外低配是另一条产品线，不是降级版

Lite 版本是独立工程，不是简单关效果。光子是中台 + 项目联合开发的。
启示：海外发行如果目标是 1GB RAM 设备，要从立项就规划 Lite 分支，不要后期补。
