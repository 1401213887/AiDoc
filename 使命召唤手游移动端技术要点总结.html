一、核心结论速览

渲染策略

  • Forward Rendering，分级 Scalable
  • 高配走 HDR + 完整后处理
  • 低配走 OnePassHDR（Tonemap 数学拟合）
  • 4 级 PBR Shader LOD

资产策略

  • BaseColor + Normal/Roughness + Metallic/AO（3 张）
  • 角色高中低配统一最高级 PBR
  • 建筑/环境走 Shader LOD
  • Houdini PCG 自动生成植被 AO/法线

工程价值

  • 制作管线工业化（PBR 三大原则）
  • GPU 烘焙：4-6h → 3-5min
  • 统一验证场景（1 主 + 6 辅）
  • 程序化 LightProbe 部署
总体基调
CODM 是 "主机画面工业化复刻到移动端" 的范本：上面定 3 大 Model（材质/光照/着色）当统一语言，下面用 PBR 三原则（验证 / 文档 / 科学性）做量产保证，技术管线给出 4 级 Shader LOD 兜住所有机型。

二、画面呈现标准（Material/Lighting/Shading Model）

关键命题
CODM 立项时面临的不是"画质天花板能多高"，而是"怎么让一群美术、外包、TA、引擎工程师对画面达成统一共识"。答案是：先把三大 Model 钉死，团队就有了共同语言。
Model定义内容CODM 实现
Material Model 材质参数与贴图布局 BaseColor 1 张 + Normal/Roughness 1 张 + Metallic/AO 1 张
Lighting Model 光源类型与组合方式 动态主光（Directional）+ Lightprobe（间接光）+ Reflection Probe（镜面）
Shading Model BRDF + 间接光积分 Lambert + GGX Cook-Torrance（直接光），SH + Cubemap（间接光）

覆盖范围：80% 可见实体共用这套 Shading Model 的变种；剩余 20%（头发、皮肤、水体、植被）走特殊方案。

三、Scalable HD 渲染管线（OnePassHDR）

高配档位

  • HDR RT 输入
  • 完整后处理（Bloom / DOF / Vignette / TAA 等）
  • 真 ToneMapping

低配档位 — OnePassHDR

  • 不分配中间 HDR RT
  • 不做后处理（节省带宽和 RT 切换）
  • 在最终 Shader 里用数学拟合近似 ToneMapping 曲线
设计精髓
低端机不能丢画面观感（HDR/Tonemap 看着是"高级"的标志），但又不能跑完整后处理 → 用 Shader 端的数学拟合换取一个 Pass，几乎免费保留 HDR 视觉风格。这跟三角洲"Tonemap 直写 BackBuffer"是同一种省 Pass 哲学。

四、4 级 PBR Shader LOD（Shading 数学拟合）

等级目标机型Shader 复杂度用途
L4 完整骁龙 835+ 等高端完整 GGX + GI Specular（Cubemap）+ GI Diffuse（SH probe）角色 + 高配建筑
L3骁龙 520 级简化 PBR 数学中端建筑
L2更低端更激进的拟合低端建筑
L1 兼容有兼容性问题的机器解决兼容问题兜底

📊 4 级 Shader LOD 阶梯图

不切 LOD 的重点
角色全档位用最完整 PBR —— 因为玩家盯着角色看的时间最长，画面风格不能跨档位漂移。建筑允许 Shader LOD，因为玩家不会盯着外墙细看。

五、PBR 材质系统

固有色贴图 1 张 (RGB)
法线 + 粗糙度 合并贴图 1 张 (Normal.XY + Roughness)
金属度 + AO 合并贴图 1 张 (Metallic + AO)

+ 接收 LightProbe 间接光
+ 接收 ReflectionProbe 镜面间接光
+ 接收 Directional Light 直接光

对比三角洲：三角洲 Normal 4 通道塞 Mask + 法线 + Roughness；CODM 走的是 Normal+Roughness 共图、Metallic+AO 共图，3 张图布局，更工业化标准。

六、光照系统（动 + 烘焙混合）

动态物体

  • 全实时计算 + 动态阴影
  • 直接光：GGX specular + Lambert diffuse
  • 间接光：IBL Cubemap + SH 球谐
  • Diffuse AO 用烘焙
  • Specular AO 由 Bake AO + Normal + EyeDir + Smoothness 计算
  • 低配直接用 AO 替代 SO

静态物体

  • 5 级 LOD（4 级 PBR 拟合 + 1 级兼容）
  • 实时计算 + Lightmap + ShadowMask 混合
  • 直接光：预烘焙 ShadowMask 阴影
  • 间接光：IBL Cubemap + 烘焙 Lightmap
  • 小范围 AO：法线梯度生成
  • 叠加 Lightmap AO

七、地形 / 植被 / Houdini PCG

地形系统（深度改造 Unity）

  • 不同地貌的 Drawcall 合并
  • 支持 Vertex Texture Fetch（VS 阶段读纹理）
  • Unity + Houdini 组合工作流（业界领先深度）
  • 团队评价："现在手游最佳的地形方案"

植被 PCG（程序化生成）

  • 原本美术逐棵手做：2 周
  • 程序化生成 AO + 法线后：2 天
  • 节省外包成本，AI 算法做烘焙降噪

LightProbe 程序化部署

用 Houdini 自动生成 LightProbe 网格，告别"美术一个个手工摆"的低效流程，迭代速度大幅提升。

八、GPU 烘焙（4-6h → 3-5min）

为什么必须自研 GPU 烘焙
Unity 原生 Enlighten 在复杂地形上烘焙一次要通宵（4-6 小时）。如果一天卡 10 张图的 bug，就是 40-60 小时无效等待。光子团队改用 GPU 烘焙后，复杂场景3-5 分钟完成，迭代速度提升 100×。
项原 EnlightenGPU 烘焙
复杂场景烘焙时间4-6 小时3-5 分钟
计算正确性黑盒有依据可调
降噪能力有限支持 AI 算法降噪
迭代时间影响线性卡 bug当日修复闭环

九、量产流程：白皮书 + 验证场景

PBR 三大原则
验证 / 文档 / 科学性 —— 这是 CODM 团队反复强调的"PBR 工业化"核心。少一个团队就会失控。

1 主 + 6 辅 验证场景

场景用途
主场景验证固有色明暗色相、不同 Roughness 下的镜面反射、金属材质反射
辅 1室内外环境光源
辅 2暖色调环境效果
辅 3强对比度明暗光照
辅 4典型室外光照
辅 5固有色是否过黑
辅 6装修色调参考

三大约束

  1. 图形技术保证：Substance Painter 与 Unity 渲染管线 95% 视觉一致（数学一致）
  2. 制作环境约束：美术只能在标准光照环境里调贴图
  3. 验收标准约束：评审只在标准环境里做，禁止在 MAX/MAYA 里看

白皮书内容

  • 输出格式定义
  • 环境配置
  • 漫反射/镜面反射率参考值
  • 各种数学原理

校验工具

  • 屏幕校色器
  • 照度仪
  • 标准色卡
  • SH/Lightmap 环境测量工具

十、关键启示与可借鉴方向

① 工业化的关键是"统一语言"，不是"最强工具"

CODM 团队反复强调三大 Model 不是为了画面更好，而是为了团队不分歧。这是大型项目的灵魂。

② OnePassHDR 是低端机保留 HDR 视感的标准方案

Shader 端数学拟合 ToneMap 曲线，用计算换 Pass，几乎免费。三角洲、CODM 都用。

③ 角色全档位最高 PBR，建筑可降级

玩家盯人物看，盯建筑不细看。分档策略要按视觉重要性，不是按物体类型。

④ GPU 烘焙是"必须自研"的中台能力

Enlighten 通宵烘焙根本不能容忍。所有大世界手游都该有自己的 GPU 烘焙工具链。

⑤ Houdini + 程序化生成是真 ROI 神器

植被 AO 法线 2 周 → 2 天，LightProbe 自动部署 —— 这种节省直接折算成项目周期。

⑥ 4 级 Shader LOD 是手游 PBR 的标配

不要做 1 级"通用 Shader"硬撑全机型，会要么拖累高端，要么压不住低端。

⑦ PBR 工业化 = 验证 + 文档 + 科学性

没有这三条，量产路上一定会失控。这不是 PBR 教科书会讲的内容，但是能不能上线的关键。
