### 核心结论（文档主线）

`avg_per_cmd = C + F/N`（`C`≈0.596 µs、`F`≈49 µs/命令列表，`F` 占 45%）
⇒ 成本在**碎片化**而非"哪条命令慢"。
三个 CVar 均作用于"分片/调度"层：`RDG.ParallelExecute=0`（−24%，已配置）、
`CombineSingleAndParallel=1`、`RDG.AsyncCompute=0`；后两者组合实测
**核时 −16.4%、帧率 +4.6%（双口径均两组分离）**。

2. **图必须渲染看**：纯审 SVG 代码 + `svg_lint.py` 全绿的情况下，仍有 **2 张图有排版事故**：
   - fig1：CVar 名过长被截断、三框横向挤压

   两张都只有**渲染成 PNG 看图**才发现，lint 抓不到（它只查文字重叠与越界）。
3. **HTML 内联 SVG 的 key 要匹配**：`data-fig="fig1"` 与 `FIGURES` 的 `fig1_全景` 不匹配，
   导致 html 里 svg 数为 0 —— 靠"数 svg 标签个数"的自检才发现。
4. **`.md` 用纯文本承载图的信息**：4 张图各写一段 ASCII 版，保证"只画在图里、正文没写的数值"
   在纯文本侧也不丢（skill §五 的硬要求）。
5. **不写 `## 目录`**：会白占一个 H2 名额。本次正文正好 10 个 H2，
