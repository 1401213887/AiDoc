## 二、落地"阻塞 Worker 补偿"改动 + 实机 A/B

- **改动**：`UE5EA\…\WaitingQueue.cpp`（`p4 edit`，未提交）：新增 CVar `TaskGraph.CompensateBlockedWorkers`（默认 1），
  在 `TryStartNewThread` / `ConditionalStandby` 里让限流名额在"本队列有 worker 阻塞在任务里"时让位（回到原生 `ThreadCount + Oversubscription`），
  并让 `WaitForYieldResume` 的让出等待不计入 oversubscription；外加一条限量 20 条的补偿日志。
- **编译**：UBT 1118 actions，exit 0；exe 内含新 CVar/日志字符串。
- **实机 A/B**（本机 32 核，限流强制 1/1，测服 13789 + 版本号伪造）：补偿0+让出0 → **卡死**（MMH 链）；
  补偿1+让出1 → 跑完；补偿1+让出0 → **卡死**（同栈）。
- **结论**：补偿改动**确实生效**（真机 20 次命中，FG/BG 两队列都命中），但本机能复现的卡死是 **MMH 形态**（占住名额的线程在"跑"不在"等"），
  **只有有界让出能解**；QA dump 的"worker 阻塞在 IO"形态在本机（32 核）没复现 ⇒ **补偿对流式形态的作用尚未端到端验证**，已如实标注。

## 三、踩的坑（可作为后续跑测 SOP）

1. **测服版本白名单**：客户端上报版本来自 `UBuildInformationConfig::Version`（user 配置 `Saved/Config/Windows/S1BuildInformationConfig.ini` 可覆盖），
   **不是**包体 `LocalVersion.txt`；当天 103 台测服没有一台 CL 匹配，靠伪造上报版本 + 选同版本命名空间（13789 = release_0.1175014）才进得去。
2. **`-CVars=` 不能把 CVar 设成 0**（实测不生效），要用 `-ExecCmds`。
3. **没进对局时 `t.CPUUsageTrack.*` 不生效**（大厅 World 里没有 CPUUsageTrack）⇒ 钉限流要直接设 `TaskGraph.MaxActive*Workers`。
4. 判卡死：不带 `-nothreadtimeout`，看 FPS 采样是否停止增长 + `GameThread timed out waiting for …`。
5. 无 pdb 时的"起名"办法：导出符号 + 偏移比栈，`.fnent` 取范围 + 反汇编 `lea` 读字符串字面量还原函数名。
