### 本轮核实的关键事实（每条都有 A/B 级来源）

- UE4 默认 PhysX 3；Chaos 在 UE4.23 引入、**UE5.0 成为默认、5.1 移除 PhysX**（版本口径有分歧，按保守理解）
- **Epic 官方实测 Chaos 并非全面更快**：Sweeps/tumbler 11.64→4.42ms、landscape 0.55→0.13ms（快）；Overlaps 2.09→2.58ms、Raycasts 0.04→0.06ms、刚体 3.17→4.76 / 5.30→8.18ms（**慢 23%~54%**）。官方归因于 LWC 双精度浮点开销
- **Chaos 不是确定性的**：Epic 官方建议不要追求 100%，只有 lockstep 才需要；开了 `SetIsDeterministic` 要付 10~30% 性能
- **最有说服力的行业实证**：《三角洲行动》多人（含手机）用 UE4，单人战役用 UE5 且**官方明确不上手机**
- Epic 官方移动端能力表：Chaos Physics **○ 支持**（复杂场景注意负载）、Chaos Destruction **△ 需降级**、Chaos Cloth **△ 仅简易设置**
- Chaos Cloth 移动端目标：**≈1ms / 角色、200~600 模拟顶点、推荐 PBD 而非 XPBD**
- **UE5 无官方 Jolt 替代**：UnrealJolt 是「与 Chaos 共存」不替换，Epic 表态 Chaos 是唯一方向、第三方集成不做支持
- 异步物理 Tick 的坑：求解器在独立线程，但 `AsyncPhysicsTickComponent` 回调**仍在 Game Thread**；输入需用 `FAsyncPhysicsTimestamp` marshal，不能在 Tick 里直读物理状态

### 踩的坑

1. **内容农场污染（本次最大收获）**：检索到多篇「2026 虚幻5 尾毛物理崩溃？腾讯天美技术总监揭秘」类文章，颗粒度极高（8000 次物理查询 / 67% cache miss / 11ms→0.8ms）。**证伪靠物理常识而非交叉验证**：它称「Chaos 与移动端 TBR 架构底层冲突」——TBR 是 GPU 光栅化架构，Chaos 是 CPU 刚体求解器，两者不在同一执行路径上，不可能「底层冲突」；且文中把 **Unity 项目《绝区零》** 列为 Chaos 案例。已把三条证伪理由写进文档 §11 留档。
   - **方法论**：高颗粒度 ≠ 高可信。凡「揭秘」类文章，先看它是否出现跨栈的因果错误（GPU 概念解释 CPU 现象），再看它举的案例是否属于该技术栈。
2. **SVG 绘制顺序**：箭头标签先画会被后画的节点框遮住（首版 fig4 的「12~20 个胶…」被截断）。**必须先把所有节点铺满，再统一画箭头与标签**。同时把节点从 5 个合并成 4 个、间隙 40→100px，才腾得出标注空间。
3. **AiDoc 索引脚本会扫 `.workbuddy/`**：归档后 `.workbuddy/physics-figs/` 里的 HTML 副本导致 README 出现两条同名记录（作者是有意索引 `.workbuddy/memory/` 的，所以不能把整个目录加进 IGNORE_DIRS）。**归档动作里要加一步：删掉中间目录的 HTML 副本，再跑 generate_index.py**。
4. **Chrome headless 截图的两个限制**：`--screenshot` 用相对路径输出位置不可控（写法与 shell cwd 不一致），统一用绝对路径；`#anchor` 锚点在 headless 下不滚动，要看中间章节得**抽出该段生成临时 HTML 再渲染**。
5. **索引归类**：新文档默认落 `99_misc`，在 `generate_index.py` 的 `03_topics` 关键词表补了 `"物理方案"` 一项（脚本注释明确允许调关键词）。
