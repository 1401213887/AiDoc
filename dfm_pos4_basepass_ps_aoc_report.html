四、关键发现

发现 1 · 寄存器侧完全健康 —— 这条路没有优化空间 重要

26 个 shader 全部 Scratch = 0（零 spill），GPR 范围 3 ~ 15（加权 8.5，中位 8）。 且 AOC 报的「Overall register footprint」= Full precision(12) 与 Half precision(22 → 打包后 11) 取大者，同样是 12。

含义：移动端着色器最常见的两个瓶颈——寄存器压力大、spill 到 scratch——在这组 shader 上都不存在。 任何"降 GPR / 防 spill / 提 occupancy"的优化在这里都是空转。

发现 2 · Misc 占 46%，且各 shader 恒定 —— 这是结构性的，不是个别材质

按 draw 加权，Miscellaneous instruction count = 426.6 / 924.8（46.1%），是最大的单一类别。 逐个看：最大的 shader（1288 条）Misc 占 41.8%，最小的 shader（127 条）Misc 占 45.7% —— 不管 shader 大小，Misc 恒在 40% ~ 51%。

我尝试把 Misc 归因到插值分量（Input component count）上，但相关性很弱（corr = 0.34）： main_0000dcc0_f18838c2 只有 20 个输入分量却带了 602 条 Misc， 而 main_00010738_da0e2140 有 40 个输入分量、Misc 是 538 条。 所以不能简单说"Misc = 插值开销"。要定位它到底由什么组成，需要看 Adreno ISA， 而 AOC 7.0.5 对二进制 .spv 不输出 ISA 反汇编（这是本轮分析的硬边界）。

可行的下一步：用 Snapdragon Profiler 抓同样的 draw， 在它的 Shader 视图里看 ISA 级别的指令构成，把 Misc 拆开。

发现 3 · Complex（EFU）指令"少而贵" —— 21 条指令占了 40% 的周期

加权下来，Complex（超越函数单元：pow / exp / log / sqrt / sin / cos）只有 15.6 + 5.9 = 21.5 条（占指令数 2.3%）， 但40.0% 的周期里都有 Complex 指令在跑（大 shader 均值 33.9%，最高 50.8%）。

对比：Texture read 6.7 条 → 16.0% 周期；ALU 419 条 → 56.2% 周期。 单条 Complex 指令的"周期占用效率"远高于其它类别，是典型的高延迟低吞吐单元。

抓手：排查材质里是否用了昂贵的 pow(x, n)（可用乘法展开）、 normalize()（含 rsqrt）、逐像素的 exp/log（能提到顶点或常量的就提上去）、 以及能量守恒类的高次幂运算。

发现 4 · half 化已经做完了 —— 这条路也没空间

ALU 16-bit = 223.9，ALU 32-bit = 195.5 → ALU 中已有 53.4% 是 half。

含义："把 float 改成 half 拿 2× 提速"这个常规建议，在这组 shader 上最多只能覆盖剩下 46.6% 的 ALU， 而 ALU 本身只占总指令的 45.4% —— 就算把剩余 ALU 全 half 化，理论上限也只有个位数百分比的指令削减。

发现 5 · 输入分量很高（加权 31.6，最高 42）

Input component count 范围 6 ~ 42，大 shader（≥1000 条）平均 32.2。 这是顶点→像素的插值带宽，属于顶点侧与 ROP 之间的固定成本， 不会因为像素 shader 内部的优化而改变。

抓手：检查 VS 的 interpolator 打包——是否所有输出都必需？ （本帧 BasePass VS 加权指令数 122.1，也是四个位置里最低的，但插值分量并未同步下降。）

发现 6 · 两个 shader 带循环

main_0000f188_84d869df（1183 条，inC=23）和 main_0000d8a0_c4ff76b5（1181 条，inC=33）各带 1 个循环。 两者都在 1000+ 指令档，但 draw 数只有 1 和 2，属于低频高价材质，优先级不高。
（对照：「烬区」地图的 BasePass PS 循环数为 0，因为那边没有 Forward+ 等动态循环光照。 攀升这里出现 2 个循环，值得确认是不是循环式反射/探针采样。）

五、优化优先级

优先级目标依据预期手段
P0 拆解 Misc 的 46% 最大单一类别，且跨所有 shader 恒定 → 全局影响 若其中含大量可消除的冗余，收益最大 用 Snapdragon Profiler 看 ISA 级指令构成；AOC 给不出
P1 削减 Complex（EFU）的使用 21 条指令占 40% 周期，单位成本最高 中高 排查逐像素 pow/exp/log/normalize；能提顶点或常量的提上去；用乘法展开整数幂
P1 降低插值输入分量（加权 31.6） 最高 42 个分量，属带宽型固定成本 中 审计 VS 输出结构体，砍掉 PS 不用的分量；注意插值器打包
P2 查看 2 个带循环的 shader 1000+ 指令且带循环 低（draw 数仅 1~2） 确认循环是否可展开或预计算
— 明确不做：降 GPR / 防 spill（已是 0 spill、GPR≤15）、 half 化（ALU 已 53.4% 是 half）、降纹理采样（加权仅 6.7 次）。这三条在这组 shader 上没有空间。

附录 · 方法学与局限

  • 数据来源：SPIR-V 由 RenderDoc MCP dump_all_shaders 一次性导出（26 个唯一 PS，按 SHA256 去重）； AOC 7.0.5 逐个编译，26/26 Compilation succeeded，0 失败。
  • 加权口径：所有汇总值按 shader 被多少个 draw 使用加权（used_by）， 而非简单平均——这样才反映实际帧开销。26 个唯一 PS 覆盖 75 个 draw。
  • AOC 是离线静态投影：看不到频率、带宽、cache 命中率。 本报告所有数字是相对口径，真机绝对值以 Snapdragon Profiler 为准。
  • ⚠️ a740 的 occupancy 字段尺度异常：本帧 26 个 shader 报 75% ~ 200%（>100% 不合常理）， 而同组 shader 在 a640 上是 50~60%。因此本报告不使用 occupancy 做任何诊断—— 好在本次结论（无 spill、低 GPR）不依赖该字段。
  • AOC 不输出 ISA：该版本对 Vulkan 二进制 .spv，-dump=all 也不会反汇编出 Adreno ISA。 这是"发现 2（Misc 构成）"无法在本轮闭环的根本原因。
