一、核心结论速览

渲染策略

  • Forward Rendering
  • 基于物理的渲染（材质/光照/相机/着色 全 PBR）
  • 预计算 GI（室内场景）
  • 动态自动曝光

三大独家技术

  • 帧预测 144FPS（GDC 2024）
  • 移动端硬件光追（GDC 2024，安卓已发布）
  • 主机级动态天气（GDC 2022）

测试数据（iPhone 14 Pro）

  • 开启帧预测 平均 FPS：97.7 → 118.3
  • 表面温度：-4 ℃
  • 电池功耗：-19%
  • 骁龙 7+ Gen2 上可达 140.2 FPS
总体评价
暗区突围是 "激进尝试新技术" 的代表 —— 帧预测、硬件光追、复杂动态天气这些原本只在 PC/主机上跑的技术，魔方团队都把它们搬到了手机。GDC 三场连续披露，技术含金量在国产手游里第一梯队。

三、144FPS 帧预测（GDC 2024 核心议题）

为什么搞帧预测
玩家既要高画质又要高帧率，但两者天然冲突。移动端高帧率还会引发带宽暴增 → 高功耗 → 高发热 → 降频 → 反而掉帧的死循环。
团队先后否决了三个方案：
  • 深度学习：依赖特定硬件单元，软回退反而负优化
  • 超分（FSR 等）：帧率提升不明显 + 邻域采样反而吃带宽
  • 插帧（最终采用）：基于已渲染帧合成中间帧

帧预测流程改造

Logic Frame N（渲染帧）

正常渲染整帧，写入 SwapChain。

Logic Frame N（同一帧内的预测帧）

  • 对 VP 矩阵插值（视点过渡）
  • 对动态对象 Uniform 参数插值
  • 不重新渲染整帧，直接合成预测帧

双 RT BasePass 拆分

避开高通 DCVS 等驱动策略下 CPU/GPU 互相等待的问题：把 BasePass 拆到 2 张 RT，第一帧上屏前先执行第一部分，让负载均匀。

骁龙 7+ Gen 2 安卓—140.2——
关键洞察
帧预测不光提帧率，还把温度和功耗都降了 —— 因为 GPU 不用每帧都重渲染整场景，平均负载下来了。这是手游优化里非常少见的"一鱼三吃"。
不平衡帧负载的隐藏陷阱
这套预测帧+渲染帧的方案 → 部分帧 CPU 重 / GPU 轻，部分相反 → 高通 DCVS 这种驱动策略会让 CPU/GPU 互相等待，抵消优化收益。
解法：把 BasePass 拆 2 张 RT，让两段帧的负载都均匀。代价：多一些带宽。

四、移动端硬件光线追踪（GDC 2024）

行业首发
暗区突围是移动端率先用硬件 RT 的产品之一，安卓版已发布，iOS 版分享时仍在开发中。

启用条件

  • 需安卓 Vulkan 图形 API（开启 Vulkan 后端）
  • 更新 ShaderConductor 交叉编译 Shader
  • 拓展 UE4 中 Vulkan 与 Metal 的 RHI 层支持 RT
  • 新一代旗舰（骁龙 8 Gen 2 等）已具备 Ray Query 硬件加速
Ray Query 优势
Ray Query 可以在 Shader 任意层级使用（顶点/片元/Compute 等），而不像传统 RTX 必须用专用 Shader Stage。对移动端开发更友好。

光追用在哪

应用用途替代方案
反射金属、水面、玻璃实时反射过去用 PlanarReflection / SSR
软阴影人物边缘平滑过渡过去用 PCF / VSM
AO真实环境光遮蔽过去用 SSAO / GTAO

📊 Ray Query 应用场景图解

移动端 RT 优化重点

  • 减少检测数量：缩小场景 BVH，做粗略剔除
  • 优化加速结构：定制 BLAS 构建策略，避开高频更新
  • 帧预测复用：屏幕空间存储光线信息 → 下一帧预测帧高效复用 RT 结果
现实坑
大部分手机帧捕获工具不支持 Vulkan Ray Query，调试 RT bug 只能 printf 大法。

五、动态天气系统（GDC 2022）

动态 vs 美术摆放
常规手游天气是美术预制好的"贴图+粒子"，玩家位置不变天气也是死的。暗区突围做的是实时演算的天气系统：大气散射、体积云、TOD 联动光照真实变化。

实现要点

动态大气散射

  • 米氏散射（Mie） + 瑞利散射（Rayleigh） 结合
  • TOD 时变，光照实时跟随
  • 低开销实现，移植自主机方案

体积云

  • 移动端低成本体积云渲染
  • 与 TOD 联动云层颜色与厚度
  • 支持暴雨、晨雾等多种气候

六、PBR 自动曝光与相机

物理相机参数

从黑暗仓库进入明亮室外时，画面亮度真实过渡（不是简单的 LUT 切换），跟人眼适应曲线一致。

这是 PBR 完整管线 (Material + Lighting + Camera + Shading) 的体现 —— Camera 是大部分手游会忽略的环节。

七、关键启示与可借鉴方向

① 帧预测是手游高帧率的"未来主流"

提帧率、降温度、降功耗"三降一升"，比超分实在。前提是要解决不平衡帧负载下的驱动策略问题。
启示：项目目标如果是 90/120/144 FPS，从立项就要规划帧预测方案，不要后期补。

② 硬件光追在新一代旗舰上已可用

骁龙 8 Gen 2、苹果 A17 Pro 等已支持 Ray Query。反射、软阴影、AO 三个用例最直接。
启示：开高画质档位的产品可以试水 RT，但要做好仅 1%~3% 用户能用的预期。

③ Ray Query 比传统 RT 更适合移动端

Shader 任意层级可用，集成到现有管线成本低。
启示：移植桌面 RT 代码到手机，优先选 Ray Query 写法。

④ 不平衡帧负载是高级技术的隐性陷阱

帧预测、异步计算、Compute 后处理这些"非传统"流程都可能踩驱动 DCVS 的坑。
启示：上线前用真机长测，不要只看平均 FPS，要看 1% Low 和温度曲线。

⑤ 物理 Camera 是被忽视的 PBR 环节

大部分项目只做 PBR Material + Lighting，忽略了 Camera 端的物理参数（曝光、白平衡、ISO）。
启示：完整 PBR 是 Material + Lighting + Camera + Shading 四件套，少一个就失真。

⑥ 动态天气 vs 美术摆放的边界正在消失

魔方把主机级动态天气搬到手机上，是品质上限的天花板提升。
启示：开放世界手游下一代标配，预制天气会越来越显得"低端"。
