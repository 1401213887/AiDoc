十大核心能力

1. 全代码库上下文理解

自动探索目录结构、理解模块依赖关系，无需手动指定上下文文件。支持 1M token 上下文窗口。

2. 自主多文件编辑与重构

跨多文件协调编辑，一个重构任务可能涉及 20-30+ 个文件的修改。

3. 测试自动修复回路

测试失败时自动读取错误、修改代码、重新运行测试，循环直至通过。

4. 原生 Git 工作流自动化

从读 Issue、写代码、跑测试到提交 PR 全流程贯通，与 GitHub/GitLab 深度集成。

5. CI/CD 集成

监控 GitHub Actions 和 GitLab CI 流水线，失败时自动提交修复。

6. MCP 可扩展性

通过开放协议连接外部工具、数据库、API。已被苹果、OpenAI 接入，成为行业标准。

7. 多智能体编排

Dynamic Workflows 支持数十到数百个并行子智能体协同工作。

8. 权限与自主模式

多级权限控制，从"每次批准"到"分类器自动判断安全/危险操作"。

9. 项目记忆 + Skills + Hooks

CLAUDE.md 持久化上下文、Skills 自定义工作流、Hooks 事件钩子、Routines 云端自动化。

10. 跨平台覆盖

终端 CLI、VS Code/JetBrains 扩展、桌面 App、Web、iOS、Slack 全覆盖。

安装指南

不需要 Node.js，自包含可执行文件，支持自动后台更新

# macOS / Linux / WSL： curl -fsSL https://claude.ai/install.sh | bash # Windows PowerShell： irm https://claude.ai/install.ps1 | iex # Windows CMD： curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

macOS/Linux 专用

# 稳定版 brew install --cask claude-code # 最新版 brew install --cask claude-code@latest # 更新 brew upgrade claude-code

Windows 专用

winget install Anthropic.ClaudeCode # 更新 winget upgrade Anthropic.ClaudeCode

需要 Node.js 18+，传统方式

npm install -g @anthropic-ai/claude-code # 不要使用 sudo！（会导致文件权限问题）

常见问题与排错 FAQ

"command not found" 或安装失败

检查 Node.js 版本（npm 方式需要 18.0+）：node --version

将 npm 全局 bin 添加到 PATH：echo 'export PATH="$(npm config get prefix)/bin:$PATH"' >> ~/.zshrc

清除 npm 缓存后重试：npm cache clean --force

认证失败 / "Invalid API key"

使用 /login 命令重新认证（支持 OAuth 和 API Key）

或设置环境变量：export ANTHROPIC_API_KEY=sk-ant-xxx

确保密钥没有多余空格或字符，可在 console.anthropic.com 重新生成

API Error: 529 Overloaded（服务器过载）

等待 2-5 分钟，这是临时性服务器问题

不要重装 Claude Code！可尝试切换到 Sonnet 模型

上下文窗口满（Context window full）

压缩对话：/compact

或清空重新开始：/clear

带指令的压缩：/compact keep only the main function names and error messages

响应缓慢 / 高 CPU 使用

切换到更快模型：/fast

定期压缩上下文：/compact

使用安全模式检查问题：claude --safe-mode

确保 16GB+ RAM，Linux/macOS 原生环境比 WSL 更流畅

隐藏命令与冷知识

/btw

旁路提问，不污染对话历史。在 Claude 工作时插入问题，回答出现在浮层中。

/rewind

时间旅行调试。可回退代码/对话/两者，三种模式灵活选择。

/insights

生成使用习惯分析报告，分析最常用命令、重复操作模式，推荐优化建议。

/voice

语音输入模式，按住空格说话，松开发送。支持 20 种语言。

/loop

周期性后台任务：/loop 60 "check server status"

Esc + Esc

打开消息历史，30 秒内可编辑并重新发送之前的提示。

双击 Esc

停止 Claude 当前操作（不退出）。比 Ctrl+C 更安全。

自诊断

/doctor 确认安装和配置；/doctor --performance 性能诊断。

Prompt 工程 — 效率提示词大全

原则 1：陈述结果，不要指挥步骤

❌ 不好 — Open userService.ts, find the validate function, add null check at line 42. ✅ 好 — Users without emails are crashing validation. Make it handle this gracefully and add a test.

Claude 比你更懂代码结构，告诉它「要什么结果」，别教它「怎么做」。

原则 2：引用已有代码做参照

✅ "Make the settings page work like the profile page"

让 Claude 去读已有代码然后模仿，比写一百字描述布局都管用。

原则 3：明确边界——告诉它「别碰什么」

✅ "Add error handling to the checkout flow. Don't change the payment provider integration."

不设边界 = Claude 可能顺手「优化」你没想让它改的地方。

万能开场：先分析，再动手

先读 src/services/ 下所有文件，理解现有架构。告诉我你看到了什么，然后等我确认再动手。

防止 Claude 一上来就瞎改。先用这句话让它探查代码库，确认方案后再执行。

根因修复（不要压制症状）

This test fails with [贴完整报错+堆栈]. Find the root cause and fix it. Don't suppress the error — fix the underlying logic. Then run the test to verify.

告诉 Claude 不要 try-catch 吞掉错误，要找到真正的问题根源。

先复现再修复（TDD 思路）

这里有个 Bug：[描述现象]。先写一个能复现这个 Bug 的失败测试，再修代码让测试通过。

强迫 Claude 走完整流程：理解→复现→修复→验证。

最小改动修复

Fix this bug with the smallest possible change. Don't refactor anything else. Show me the diff and explain why this one line was the problem.

防止 Claude 修一个 bug 顺手重构半个文件。

四步重构：理解 → 方案 → 执行 → 验收

第1步：Read src/modules/payment/ thoroughly. Map every file, dependency, and public API. Tell me what's coupled to what. 第2步：Based on your analysis, propose 3 refactoring approaches. For each, list what would break. 第3步：Implement option 2 step by step. After each file change, explain what changed and run related tests. 第4步：Review all changes. Any broken tests? Leftover old references? Public API unchanged?

对付复杂重构的神器。每一步都让 Claude 停下来等你确认。

切片策略：圈定范围

We need to migrate from REST to GraphQL in the user module. Do NOT touch the database layer or the frontend. Only change the controller and service layers. List exactly which files you'll modify before starting.

对付超大重构：先画好边界，防止 Claude 扩散修改范围。

匹配现有测试风格

Write tests for UserService.ts covering: happy path, null inputs, boundary values, and all error branches. Match the pattern used in tests/user.test.ts — same describe/it structure, same assertion library, same mock style.

告诉它参考哪个文件，比手写测试模板快十倍。

边界值轰炸

Test this date parser with: empty string, null, "2024-02-29" (leap year), "2023-02-29" (invalid), "0000-00-00", strings with timezone offsets, 13th month, 32nd day.

直接列举边界值，Claude 会生成全部测试用例。

反向测试（验证拒绝非法输入）

Write tests that should deliberately FAIL with good error messages for these invalid inputs: [列举]。Verify the system rejects bad data cleanly, not crashes.

不仅要测正常路径，还要测系统「拒绝」的行为是否优雅。

安全性优先审查

Review this PR for: SQL injection, XSS, unvalidated user input, hardcoded secrets, missing auth checks, path traversal. Ignore style issues.

指定审查维度，忽略代码风格，聚焦安全问题。

性能审查

Review the database queries in this PR. Flag: N+1 queries, missing indexes, queries in loops, unbatched inserts, SELECT * without pagination.

对比审查

Compare current implementation with version from commit abc123. List what changed in behavior, not just code. Flag any regression risks.

让 Claude 做 diff 审查，标注行为变更和回归风险。

放进 CLAUDE.md 的行为约束（一次配置，永久生效）

Always explain your plan before editing files. Never change more than 3 files in one turn without asking. When you see a type error, check if it's a real bug or a type definition issue before fixing. Prefer editing existing files over creating new ones. When in doubt about a library API, search the codebase for existing usage patterns first. Run `npm run build` after any import or dependency change.

这些不是口语对话 prompt，而是放在 CLAUDE.md 里的行为规则。每次 Claude 执行任务时自动遵循。
