一、核心结论速览

渲染策略

  • 移动端 前向渲染 + 自定义 SRP（与原神同源）
  • 战斗场景 固定相机 → 渲染开销可预测
  • 探索场景类似原神，但场景体量更小

核心技术

  • 角色 NPR 在原神基础上加强 金属/科幻质感
  • 战斗 UI 为 立绘 + 3D 模型混合
  • 大量 预渲染过场 与实时镜头无缝混剪

预算/Format

  • SceneColor R11G11B10
  • 战斗专用 Composition RT（角色描边/技能光效层）
  • Shadow 1~2 级 CSM
星穹与原神的关键差异
星铁是 回合制 + 半开放，相机不像原神那样自由旋转。这给了它两个工程红利：
① 战斗时相机轨道固定，剔除 / LOD 决策可预先烘焙；
② 探索场景规模可控，可以塞更多静态烘焙细节而不付带宽代价。

三、渲染管线与 Pass 顺序

Pass 1 · ShadowMap（1~2 级 CSM）

战斗场景常用 1 级，探索常用 2 级。Shadow Bias 与角色独立设置，避免角色脚下"飘"。

Pass 2 · Depth Prepass（仅探索）

战斗模式跳过，因为角色数量少且相机固定，完整 Z-Cull 收益不大。

Pass 3 · Opaque BasePass

地表 → 建筑 → 静态道具 → 敌人 → 我方角色。每类有自己的 Material 模板，角色一定最后绘制，便于后续角色专用 Composition。

Pass 4 · Outline 描边

战斗模式下，描边可以做到分类型染色（火属性偏红、冰属性偏蓝），通过 Material ID 控制。

Pass 5 · Sky / Atmosphere

探索模式启用，战斗模式常用静态 Cubemap 替代以省 GPU。

Pass 6 · Transparent / Effects

技能光效、能量场、屏幕空间扭曲。星铁的技能特效是 GPU 大头，移动端高档可达单个技能 80~120 ms 渲染时间峰值。

Pass 7 · PostProcess

Bloom + 色调映射。战斗胜利动画时叠加电影级 DOF + Vignette。

四、角色 NPR 升级版

金属与发光质感强化

  • 角色身上大量金属/能量/科幻贴片：MatCap + Anisotropic 高光近似
  • Emissive 流光：贴图 UV 滚动 + Noise 调制，常用于"星轨"流光线
  • 战斗待机姿态下的 Pulse 光效：屏幕空间 sin 函数 + 时间偏移

面部刻画

  • 沿用 SDF 面部贴图（与原神同思路）
  • 瞳孔高光：单独 Mesh 顶点，放大 emissive 通道
  • 眉毛/睫毛：开启 Z-Test 可穿透前发显示（高档）/ 直接显示（低档）

头发 anisotropic 高光

星铁角色头发常带霓虹色高光带（开拓者/银狼/卡夫卡的发尾染色），实现：

  • 沿头发 tangent 方向的 Anisotropic 计算
  • 2 层高光：主色（白）+ 次色（角色专属调色）
  • Ramp 贴图调整高光位置，让其位于"发型最美的位置"，不是物理正确位置

五、战斗镜头与特效

大招演出

  • "大招演出"是星铁特效预算最高的部分，常占用整帧 60%+ 时间
  • 采用 多层 RT 合成：背景虚化 + 主角 + 屏幕空间几何切割 + UI 文字
  • 临时切相机至专属"舞台"空间，只渲染该角色和必要环境元素
  • 移动端高档可保持 60 fps，低档允许降至 30 fps 但分辨率降到 720P

属性色调

属性主色调典型特效

火橙红体积光 + Emissive 燃烧贴图

六、场景资产规格

地形

  • 不像原神那样开放，使用 预制 Tile 拼接
  • 4~6 层 Splat + 顶点色控制
  • 不使用 SVT，而是 Atlas + Mesh Streaming

静态物件

  • BaseColor 1024~2048 + Mask
  • 大量场景使用 Mesh Decal 增加细节，避免高分贴图
  • Lightmap 烘焙 1024² 区块，分块加载

角色

  • 面数 30~40k（高于原神探索模式角色）
  • 骨骼 80~120 根
  • 表情用 Blend Shape，约 30 个 morph 目标

UI

  • 大量动态布局 + 角色立绘渲染
  • 立绘有 实时光照模拟（光源跟随手指或鼠标）
  • 主菜单是 3D 场景实时渲染，非视频

七、后处理与电影感

电影感是产品定位
星铁的探索/战斗与原神画风同源，但战斗演出强调电影感——这意味着 DOF/Bloom/Vignette/Color Grading 不能砍。

八、移动端性能与内存

战斗专用优化

  • 战斗开始前预加载所有出战角色 + 敌人技能资源（避免战中 hitch）
  • 固定相机意味着可预先剔除场景——不在视野内的物件根本不上 GPU
  • 大招特效 RT 复用：分配一组 4 张 Composition RT，按需调度，避免重复创建

探索内存策略

  • 分块 Streaming，每块 50~80MB 资源
  • 角色队伍：4 个出战 + 缓存 4 个备用，超出走 LRU
  • 纹理压缩：ASTC 6×6 普及，关键贴图 ASTC 4×4

分档

  • 极低/低/中/高/超高，自适应分辨率 540P~1080P
  • 低档关 SSAO/SSR/Bloom，仅保留 Tonemap
  • "超高"档对标 PC，旗舰机才开放

九、关键启示

对回合制 / 半开放产品

  1. 固定相机 = 大量预计算和 baked 优化的契机
  2. 战斗与探索的渲染管线可以"差异化"，不必一套通吃
  3. 过场镜头是炫技舞台，应允许它"超过帧预算"换取观感

对 NPR 二代项目

  1. 金属/科幻质感可以靠 MatCap + Anisotropic 实现，不必上 PBR
  2. 属性色调系统化（统一 LUT/调色板）能极大提升美术效率
  3. 立绘的 UI 实时光照是低成本但高观感的爆款元素
