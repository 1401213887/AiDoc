四、关键发现与根因分析

🔴 头号瓶颈：DeferredShading > MP_Map_1.BP_ParentCommonEnvLight1_Cloud（eid=3796，22% / 1.43ms）

现象：单个全屏 Draw 占满帧的 22%。AOC 显示 Overall GPR=44（偏高）、ALU fiber occupancy=25%（偏低）、exposed long latency=45.6%（近半周期卡在等访存且无 wave 掩盖）。
根因：这是一个 24988 条指令的超大 PS（体积云 + 延迟光照）。寄存器压力(GPR=44)直接压低了 occupancy，导致没有足够并发 wave 来掩盖访存长延迟——形成 "高 GPR → 低 occupancy → 延迟暴露" 的恶性链条。32-bit ALU 占 7971 条（half 仅 17%），精度浪费也加重了寄存器与 ALU 负担。
优化方向（按收益排序）：
  • 降 GPR 是关键：拆分 shader、缩短变量 live range、避免大本地数组/动态索引；目标把 GPR 压到 ≤32 以解锁更高 occupancy 档位。
  • full → half 化：7971 条 32-bit ALU 中大量光照/颜色计算可用 mediump/half，既减 ALU 周期又降寄存器压力。
  • 体积云本身：考虑降低 raymarch 步数 / 半分辨率渲染 + 上采样 / 时域复用，从源头减少这个 PS 的工作量。

🔴 次热点：ShadowProjection > RenderMobileShadowProjection（eid=2324，12.5% / 0.81ms）

SPIR-V 实测特征（非臆测）：该 shader 是本帧最大的 PS（41KB）。其资源绑定清晰可见：DAGTreeDataBuffer / DAGChunkInfosBuffer / DAGFactorListsBuffer / DAGTileIDToBufferOffsetBuffer（DAG 加速结构）、Static/Dynamic_IntersectPageTablePerClipmap + MMHPhysicalTexture（虚拟阴影贴图页表 + 物理图集）、以及 SMRTMaxRayCount / SMRTSamplePerRay / SMRTRayLengthScale（屏幕空间光线步进软阴影参数）。
AOC 实测验证（已补全）：occupancy=100%（并发已拉满）但 exposed long latency=50.1%（仍有半数周期卡在等访存）、GPR=12（很低，不是寄存器问题）。这是教科书式的访存/依赖链 bound——并发已无提升空间，延迟掩盖不住只能从"减少访存"下手。Complex(EFU)=15.3% 偏高也印证了光线步进里的超越函数/除法开销。实测数值与下方基于资源结构的定性判断完全吻合。
定性判断（资源结构）：这是 MMH 虚拟阴影贴图 + SMRT 屏幕空间光线步进的全屏软阴影合成 Pass。其特征是大量 StructuredBuffer 随机访存 + 光线步进循环（97 条 flow control 印证循环/分支密集），确属访存/依赖链 bound。优化方向：降低 SMRTSamplePerRay/MaxRayCount、收紧 FadeDistance 提前剔除远处像素、对页表查询做局部性优化、缩短 load→use 依赖链。

🟡 几何密集 Pass：MobileBasePass + MobileRenderPrePass（合计 22.5% / 1.46ms，426 Draw）

现象：BasePass(222 Draw, 0.79ms) + FullDepthPrepass(204 Draw, 0.67ms) 共 426 个 Draw。单 Draw 平均仅几 μs，说明瓶颈不在单个 shader，而在 Draw Call 数量 / 顶点吞吐 / 提交开销。
优化方向：合批（静态合并 / Instancing）、加强遮挡剔除减少 BasePass overdraw、检查 DepthPrepass 是否对所有物体都必要（移动端 prepass 收益需权衡）。

🟢 健康项：后处理链路

TAA / Tonemap / AmbientOcclusion_HorizonSearchIntegral 三个全屏后处理 PS 的 AOC 指标均健康（GPR=13、occupancy 75~87%、Scratch=0）。它们的耗时主要来自全屏像素量 + 纹理采样带宽（AmbientOcclusion/TAA 纹理占比 32%），属正常填充率开销，非寄存器瓶颈，暂不需要 shader 级优化。
